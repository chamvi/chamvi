Stores and repositories ​

Runs, steps, checkpoints, effect results, artifacts, agent state, locks, idempotency keys and agent revision markers sit behind services: the engine receives a RunService (runService), a StepService (stepService), a CheckpointService (checkpointService), an EffectService (effectService), an ArtifactService (artifactService), a StateService (stateService), a LockService (lockService), an IdempotencyService (idempotencyService) and an AgentRevisionService (agentRevisionService) that hold every rule (lineage, the update guards, updatedAt, the claim lease, the list queries, the highest checkpoint, insert-if-absent artifacts, the keyed artifact that keeps its id, the lease and claim expiry) over the repository ports of @chamvi/store. A port only stores, reads, locks a row and runs a query:

There is no store aggregate: the engine takes each service by name. Every service has an interface (IRunService, IStepService, ..., IConversationService), and the engine, the channels and the HTTP API are typed by it: any object that satisfies the interface can stand in for the class, with or without a repository behind it (a fake in a test, a wrapper that records or fails calls). createConnectionVault() takes the connection service and a lockService on the same lock storage, e.g. for the WhatsApp session store. Pass the services as new Engine({ runService, stepService, checkpointService, effectService, artifactService, stateService, lockService, idempotencyService, agentRevisionService, conversationService, agents }); use engine.runService.findOne(id) or engine.stateService.findOne(agent, key) for direct access. Conversation storage alone does not enable memory: configure conversations: { authorize, limits? } on the engine and opt agents in.

Query methods ​

findOne(...) returns one record or undefined. find(...) returns the repository's existing collection shape: run queries return { data, total }, while steps, artifacts, state and agent revisions return arrays. Conversation item/note queries return { data, total } through findItems and findNotes.

The matching OrFail method returns the same result when it exists. findOneOrFail(...) throws for undefined; stored state values such as null, false, 0 and '' are valid results. findOrFail(...) throws when the selected array or page is empty, including a run query with limit: 0 or an offset beyond the last result even when total is nonzero. Query validation is unchanged: conversation queries require limit >= 1, so their limit: 0 is a validation error. Qualified queries follow the same rule: findDocumentsOrFail, findItemsOrFail, findNotesOrFail and findOneNoteOrFail.

A missing single run or artifact uses RunNotFoundError or ArtifactNotFoundError; other missing repository results use RepositoryNotFoundError. Backend failures and validation errors pass through unchanged. Leases and mutations retain their domain operations, such as claim, renewClaim and beginTurn.

ts
const run = await engine.runService.findOneOrFail(runId);
const { data, total } = await engine.runService.find({ agent: run.agent, limit: 20 });
const artifacts = await engine.artifactService.find(runId);

Rules every repository keeps ​

A repository stores, reads, locks a row and runs a query; it decides nothing. The port suites check each rule on your backend.

  1. Store as given. No status, owner or revision compare, no limit, default, time stamp, derived field or choice of domain error, and no clock: the services decide and hand the repository the finished row.
  2. No aliasing. Values are copied in and out. Mutating an object after passing it to a repository, or one a repository returned, never changes what it holds.
  3. Transactions. transaction(fn) hands fn a repository bound to the transaction; a single-row read there (findOneById, findOneBy) locks the row until the transaction ends, so two callers never interleave between a read and its save, also across processes. A throw rolls everything back.
  4. Six storage errors, each with the entity's label and a fixed message, never a value: EntityNotFoundError, EntityConflictError (a taken key or unique value), EntityRelationError (a missing referenced row, or a removed row another references), EntityDeadlockError, EntityQueryError (a where with an undefined value, an empty removeManyBy, an operation the port does not offer), EntityInvalidError (a value the table refuses: a missing required column, a failed check, a value too long).
  5. Orderings the storage owns. findMany sorts strings by code point (case sensitive); steps and conversation items keep a storage key in the order they were stored (STEP_STORED_ORDER, CONVERSATION_ITEM_STORED_ORDER).

Rules the services keep ​

  1. One expiry rule. A claim, key or lock created at time T with ttlMs is expired at exactly T + ttlMs and can be taken over at that instant.
  2. Time comes from the clock. Every service that compares time takes an IClock and reads it after its locked read, never the database's clock, so tests can drive time and replicas agree on one rule.
  3. Atomic means atomic across callers. runService.create, runService.claim, runService.renewClaim, idempotencyService.claim, lockService.acquire, artifactService.create and artifactService.save hold under concurrency, also across processes.
  4. Ordering. runService.find orders by createdAt ascending, ties broken by id ascending, or both descending with order: 'desc' (newest first); total ignores limit and offset. artifactService.find orders the same way. agentRevisionService.find orders by agent name in code-point order.
  5. Guards throw. runService.update throws InvalidRunStateError when expectStatus does not match, or when expectOwner is given and the claim is absent or held by another owner (expiry is not checked there: a lease is lost once taken over), or when expectWaitId is given and the run's wait id differs or it has no wait point. It throws RunNotFoundError for an unknown run.
  6. Checkpoints. checkpointService.save keeps the highest stepIndex; an equal index replaces.
  7. State filters. stateService.findDocuments where matches top-level fields by equality and lists by document id in code-point order.
  8. Run references. stepService.create, checkpointService.save and conversationService.beginTurn for a run the store does not hold throw RunNotFoundError and write nothing (the repository reports EntityRelationError).
  9. Artifacts. artifactService.create resolves false and keeps the stored metadata and bytes when the id exists, or when key is given and the run already holds an artifact under that key. artifactService.save is an atomic upsert by (runId, key) and resolves the stored metadata: an absent key inserts the artifact as given, an existing one keeps its id, agent and createdAt and replaces mediaType, filename (a missing one removes it), size and the bytes. The key is private to the store: no read returns it, and findOneByKey(runId, key) is the only lookup by it. read returns a plain Uint8Array (no Buffer or other subclass); findOne and find return metadata only.

The interfaces ​

ts
/*
 * Copyright (c) 2026.
 * Author Peter Placzek (tada5hi)
 * For the full copyright and license information,
 * view the LICENSE file that was distributed with this source code.
 */

import type { IQuery } from '@rapiq/core';

/**
 * A stored row: a plain object keyed by property name.
 */
export type EntityRecord = Record<string, any>;

/**
 * A where of `findOneBy`, `findManyBy` and `removeManyBy`: each given
 * property matches its value, `null` (a missing value) or, given an
 * array, any of the array's values (a `null` in it matching a missing
 * value); every given property must match. A
 * property present with the value `undefined` is refused with
 * `EntityQueryError` (omit it instead): a filter never silently widens.
 */
export type EntityWhere<T> = {
    [K in keyof T]?: T[K] | T[K][] | null;
};

/**
 * One page of `findMany`: the rows and the total of the whole selection.
 */
export type EntityFindManyResult<T> = {
    data: T[];
    meta: {
        total: number;
        limit?: number;
        offset?: number;
    };
};

/**
 * The generic repository port of one entity. A repository decides
 * nothing: it stores, reads, locks a row, runs a query and reports
 * `EntityNotFoundError`, `EntityConflictError`, `EntityRelationError`,
 * `EntityDeadlockError` or `EntityQueryError`; status compares, limits, defaults and time stamps
 * belong to the service using it.
 */
export interface IEntityRepository<T extends EntityRecord = EntityRecord> {
    /**
     * Run a rapiq query (fields, filters, sort, pagination) over the
     * entity. Inside `transaction()` it locks none of the rows it returns:
     * a service that changes a listed row reads it again with a single-row
     * read first. A row read with a field selection holds those fields
     * only: `save` of it writes what changed, `upsert` and `upsertMany`
     * refuse it (`EntityQueryError`), by object identity as `save` decides.
     */
    findMany(query: IQuery): Promise<EntityFindManyResult<T>>;

    /**
     * The row with this primary key, or `null`. Inside `transaction()` the
     * row read through the handed-in repository is locked until the
     * transaction ends. An `undefined` or `null` id is refused with
     * `EntityQueryError`.
     */
    findOneById(id: string): Promise<T | null>;

    /**
     * The one row matching the where, or `null`. Inside `transaction()`
     * the row read through the handed-in repository is locked until the
     * transaction ends.
     */
    findOneBy(where: EntityWhere<T>): Promise<T | null>;

    /**
     * Every row matching the where (`EntityWhere`), however many values
     * an array holds. Inside `transaction()` it locks none of the rows it
     * returns: a service that changes a listed row reads it again with a
     * single-row read first.
     */
    findManyBy(where: EntityWhere<T>): Promise<T[]>;

    /**
     * A new entity object; nothing is stored. `save()` inserts it.
     */
    create(data: Partial<T>): T;

    /**
     * Copy `data` onto `entity` and return it; nothing is stored.
     */
    merge(entity: T, data: Partial<T>): T;

    /**
     * Insert or update, decided by object identity: an entity object
     * returned by `create()` is inserted (`EntityConflictError` if its key
     * exists), an entity object returned by a read is updated (its changed
     * properties only). A spread copy of a created entity is neither and
     * counts as an update. Resolves the stored row as a read returns it
     * (a new object, itself marked as read).
     */
    save(entity: T): Promise<T>;

    /**
     * Insert, or replace the row with the same key; no condition. Resolves
     * the stored row as a read returns it. A row `findMany` read with a
     * field selection is refused (`EntityQueryError`): it would clear the
     * fields it lacks.
     */
    upsert(entity: T): Promise<T>;

    /**
     * `upsert` of each entity, in one transaction (all or nothing), in as
     * few statements as the driver allows, however many there are: no
     * condition, a later entity of the same key replaces an earlier one.
     * An empty array stores nothing. Resolves the stored rows as reads
     * return them, in input order.
     */
    upsertMany(entities: T[]): Promise<T[]>;

    /**
     * Delete the entity's row.
     */
    remove(entity: T): Promise<void>;

    /**
     * Delete the rows of every given entity.
     */
    removeMany(entities: T[]): Promise<void>;

    /**
     * Delete every row matching the where (`EntityWhere`) without
     * reading them out, and resolve how many it deleted. An empty where is
     * refused with `EntityQueryError`: there is no remove-all form. A row another entity references is refused as by
     * `remove`, unless the reference removes or clears the referencing
     * rows with it (the driver's schema decides).
     */
    removeManyBy(where: EntityWhere<T>): Promise<number>;

    /**
     * Check that every row `data` references exists, else
     * `EntityRelationError` naming the referenced entity.
     */
    validateRelations(data: Partial<T>): Promise<void>;

    /**
     * Check that no other row holds a unique value of `data`, else
     * `EntityConflictError`; `existing` is the row being updated, which
     * may hold its own values.
     */
    checkUniqueness(data: Partial<T>, existing?: T): Promise<void>;

    /**
     * Run `fn` in one transaction with a repository bound to it. Use only
     * the handed-in repository inside `fn`: a call on the outer repository
     * is not part of the transaction, and a write through it on a row the
     * transaction holds waits for `fn` while `fn` waits for it, so neither
     * ends. A single-row read on the handed-in repository
     * (`findOneById`, `findOneBy`) locks that row until the transaction
     * ends, a list read (`findMany`, `findManyBy`) locks nothing, so a
     * service that changes a row reads it with a single-row read first. A
     * throw rolls everything back, also the identity of entity objects
     * saved in it: a retry saves them as the first attempt did. Await every
     * call on the handed-in repository before `fn` settles: a call that
     * runs after the transaction ended is refused with a storage error.
     */
    transaction<R>(fn: (repository: this) => Promise<R>): Promise<R>;
}
