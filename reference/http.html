@chamvi/http ​

REST, SSE, MCP, the http, mcp and webhook channels and the /channels/<name> mount for chamvi agents, on routup. The public API of packages/http/src/index.ts.

bash
npm install @chamvi/http @chamvi/core --save

@chamvi/core is a peer dependency. See HTTP API & MCP for the behaviour.

createHttpApp ​

ts
function createHttpApp(options: HttpAppOptions): App; // routup App

The store, the agents and the clock come from engine (engine.store, engine.listAgents(), engine.clock). The agents are read from the engine on every request, so an agent registered, replaced or removed at runtime gets (or loses) its routes, webhook subscriptions, GET /agents entry, schedules and MCP run_<agent> tool at once; a run_<agent> definition is built once per agent object, and one that fails for an agent registered after construction goes to onError and that tool is left out. agents narrows the served agents to the named ones, checked at construction: the others, also agents registered later, get no routes or MCP tools in this app (a mounted channel serves every agent subscribing to it), and a named agent removed from the engine answers 404. agentIssues lists agents that failed to load as GET /agents issues. HttpRouteContext.agents is read from the engine on every access. Throws InvalidAgentDefinitionError for a name in agents the engine lacks or that is given twice, an empty auth array and an invalid routes entry (a path that is not static, a duplicate method and path, a first segment of a built-in route such as agents, runs or channels, or the metrics path, all compared case-insensitively).

channels lists the channels mounted at POST /channels/<name> (each needs an in and must be the object the engine holds under its name, else InvalidAgentDefinitionError). connections returns the connection handles (IConnectionHandle of @chamvi/core: name, type, status(), widgets(), subscribe(), actions.reset?) served at /connections; it is called per request, and @chamvi/app passes every AppToken.CONNECTIONS contribution. routes takes extra routes from other packages, such as the dashboard of @chamvi/ui:

ts
export type HttpRouteMethod = 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';

export type HttpRouteRequest = {
    /** URL, method, headers and signal; without the body, which only readBody() reads. */
    request: Request;
    /**
     * Runs the app's authenticators over the request, once per request (every
     * call, and a built-in route's check, shares the result): 401 with
     * `WWW-Authenticate: Bearer` without a principal, 403 when `permission`
     * is given and not granted. A route that never calls it stays unauthenticated.
     */
    authorize(permission?: string): Promise<Principal>;
    /**
     * The raw body, at most `bodyLimit` bytes: 413 above it (content-length
     * refused unread, else drained like readJsonBody), 415 for a non-JSON
     * media type with a non-empty body; an empty body is a 0-length array.
     * Memoized: every call answers the same bytes (or the same error).
     */
    readBody(): Promise<Uint8Array>;
    /**
     * The path below the route's `path`: `''` for `path` itself, else the raw
     * (still percent-encoded, case kept) rest starting with `/`, e.g.
     * `/assets/app-1a2b.js`; never the query. Only a `prefix` route sees more than `''`.
     */
    subpath: string;
};

export type HttpRouteResult = {
    status: number;
    /** Set on the response; a `content-type` here wins over the body's default. */
    headers?: Record<string, string>;
    /**
     * A `Uint8Array` is sent as is (`application/octet-stream` unless
     * `headers` names a `content-type`); objects, arrays, numbers and booleans
     * as JSON, a string as `text/plain`; `undefined` or `null` answer an empty body.
     */
    body?: unknown;
};

export type HttpRouteContext = {
    engine: IEngine;
    /** The agents the app serves, read from the engine on every access. */
    agents: readonly Agent[];
    clock: IClock;
    onError: (error: unknown) => void;
    /** The app's `basePath` (`''` by default), e.g. to build absolute links. */
    basePath: string;
};

export type HttpRoute = {
    method: HttpRouteMethod;
    /** Static path under basePath (no ':' '*' '{'), e.g. '/ui'; also its metrics label. */
    path: string;
    /** false: skipped by the app's rate limiter (callers that never retry, e.g. webhook senders). Default: limited. */
    rateLimit?: false;
    /**
     * true: the route also serves every path below `path/` (same method),
     * handing the rest as `request.subpath`; labelled `<path>/*` in metrics.
     */
    prefix?: true;
    /**
     * Not authenticated by the app's authenticators unless the handler calls
     * `request.authorize()`. Thrown @ebec/http and core errors render like any route's.
     */
    handler: (request: HttpRouteRequest, ctx: HttpRouteContext) => Promise<HttpRouteResult>;
};

The app's authenticators do not guard an extra route. A handler that needs them calls request.authorize(permission?): it resolves the caller's Principal (the authenticator chain runs once per request), answers 401 with WWW-Authenticate: Bearer without one and 403 when the principal lacks permission.

Channel HTTP request limits ​

channelRateLimits?: Record<string, false | ChannelRateLimitOptions> selects the HTTP intake policy for each mounted channel, without changing run execution capacity:

  • An omitted entry inherits the general rateLimit bucket (default 300 requests per 60 seconds per client IP), shared with REST and other unconfigured channels.
  • { max, windowMs? } replaces that bucket for the channel with its own per-client bucket, separate from REST and other configured channels. windowMs defaults to 60,000. Explicit channel limits also work when the general rateLimit is false.
  • false removes request limiting only for that channel's mounted POST /channels/<name> and subpaths. It does not disable authentication, signatures or body-size checks. Other methods and unknown channel paths do not gain the exemption.

The keys must exactly name mounted input channels. max must be a positive safe integer; windowMs a positive integer no greater than 2,147,483,647. Invalid policies throw InvalidAgentDefinitionError before serving. Buckets are local to this HTTP app, not coordinated through the run store. Refusals remain JSON 429 responses with Retry-After and rate-limit headers.

The same options pass through httpModule() in @chamvi/app. See GitHub intake behind an ingress for finite and disabled examples. trustProxy defaults to trusting no forwarded headers; restrict it to known proxy source addresses or CIDRs, never blindly trust arbitrary client headers.

    idempotencyKey?: (payload: unknown) => string | undefined;
    concurrencyKey?: (payload: unknown) => string | undefined;
};

/** Makes webhook subscriptions for one channel name. */

    /** `path` starts with `/`; the subscription id is `webhook:<path>`. */
    on(path: string, options?: WebhookSubscriptionOptions): ChannelSubscription;
};

httpChannel({ untrusted: true }) and mcpChannel({ untrusted: true }) opt the REST and MCP intake into the run-taint boundary, for callers that relay text written by others (an OpenClaw MCP principal forwarding chat messages): every run they start is tainted (channel:http/channel:mcp), so outbound tools wait for approval. Both default to trusted, since the caller is an authenticated principal. In an @chamvi/app app, configure the built-in http module: httpModule({ untrusted: { mcp: true } }) (or http: true) in createApp({ modules }).

The engine refuses an http.on() subscription unless it holds httpChannel() (REST and MCP keep separate idempotency scopes through the two channel names), and a webhook.on() one unless it holds the webhook channel. webhook.on() throws InvalidAgentDefinitionError for a path that does not start with /. See Channels.

Authenticators ​

ts
type Authenticator = (request: Request) => Promise<Principal | undefined>;

function staticTokens(options: StaticTokensOptions): Authenticator;
function authup(options: AuthupOptions): Authenticator;
function oidc(options: OidcOptions): Authenticator;

An authenticator resolves undefined for a request it does not recognize and throws a 401 for credentials it rejects. staticTokens throws InvalidAgentDefinitionError for an empty tokens array, a token value shorter than 16 characters, a missing id or a value given twice; oidc for an empty issuers list, an issuer without audience or a missing principal.

ts
const Permission: {
    ALL: '*';

    STATE_WRITE: 'state:write';

function assertMcpRunTool(agent: Agent): void; // throws InvalidAgentDefinitionError like createHttpApp

assertMcpRunTool builds the agent's run_<agent> MCP tool definition and throws what createHttpApp would throw for it (a tool name above 64 characters, a payload schema MCP cannot compile); the app runs it on every folder agent before registering it. createHttpApp reports a folder agent's failure (one the engine holds at a revision) to onError and skips its tool instead of throwing.

Matching uses core's hasPermission(principal.permissions, permission): true for a granted *, or for a grant with the same number of : segments whose every segment is equal or *.

import type { IEngine } from '@chamvi/core';

export interface IShutdown {
    /** True from the first `shutdown()` call on; `/readyz` then fails. */
    readonly shuttingDown: boolean;
    /**
     * Runs `fn` during the shutdown, in the order added, after readiness
     * failed and before the server closes; returns an unsubscribe.

    onShutdown(fn: () => void | Promise<void>): () => void;
    /** Idempotent: every call returns the same promise. */
    shutdown(): Promise<void>;
}

export type ShutdownOptions = {
    /** Drained on shutdown; its `clock` times the delays. */
    engine: IEngine;
    /** srvx `Server` (pass `gracefulShutdown: false` to `serve`). */

    /** Time for load balancers to see the failing readiness. Default 0. */
    readinessDelayMs?: number;
    /** Default 30 s. */
    drainTimeoutMs?: number;
    /** Wait for open connections after the drain, then close them. Default 5 s. */
    closeTimeoutMs?: number;
    /** Default `console.error`. */
    onError?: (error: unknown) => void;
};

GET /runs takes filter[parent]=<run id> (once, else 400 filter[parent] takes one run id.) next to filter[agent], filter[status] and filter[waiting] (approval or dispatch, once, else 400 filter[waiting] takes approval or dispatch.; the wait point's kind): the runs whose parentRunId it is, under the same read rule (an agent-scoped reader adds filter[agent]). Runs carry parentRunId and subtreeUsage when set; POST /runs/:id/approve answers a run waiting on dispatched runs with 409 invalid_run_state, and approve_run refuses it.

selected follows engine.approve()'s rules (see Approvals and HTTP): a selection that does not fit the wait point is 400 validation_error.
