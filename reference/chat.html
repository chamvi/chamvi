@chamvi/chat ​

Chat channels on the Chat SDK. The public API of packages/chat/src/index.ts and src/module/index.ts.

bash
npm install @chamvi/chat @chamvi/core @chamvi/http chat --save

@chamvi/core, @chamvi/http and chat (^4.45.0) are peer dependencies; @chamvi/app is an optional peer, imported only by @chamvi/chat/module. The package imports no platform SDK: platforms ship as their own packages on the public platform seam, WhatsApp Web as @chamvi/chat-whatsapp, Discord as @chamvi/chat-discord.

Option
chat, adaptersThe Chat and its adapters, each wrapped by createChatIngressAdapter() and registered with that Chat under its name. The channel owns the Chat alone; another channel cannot take it
allowMessage(incoming)Required for every adapter: whether a message may start runs at all
resolveInvoker(incoming)The runs' invoker; none by default
nameDefault chat (the agent name rule)
webhooksAdapter names served at POST /channels/<name>/<adapter>; without any the channel has no in
untrustedDefault true: every run is tainted channel:<name>
accountThe conversation account alias; default the adapter's name
defaultAddressAn address of to(); none by default (an ungated sink for tainted runs)
connect({ signal, clock }), disconnect()Called on start (after the Chat initialized) and on stop; connect must settle once signal aborts
approvalUrl(ref)Required to send an approval; with answers, only for one with options, a trust-gate notice or one to a group
answers{ model?, timeoutMs? }: approvals answered by a reply in a direct chat (below); off by default; needs resolveInvoker
voice{ model, maxBytes?, maxSeconds?, timeoutMs?, label? }: voice messages transcribed into text (below); off by default
historyOnly 0: no platform history is fetched
timeoutMsOne send's bound, default CHAT_TIMEOUT_MS
maxTextCharsThe longest message sent (UTF-16 code units), an integer from 1 to CHAT_TEXT_MAX_CHARS, default CHAT_TEXT_MAX_CHARS (Discord passes 2000)
onErrorFailures nobody awaits (refused and failed messages, stop)
platformA platform package's hooks (IChatPlatform, below); none by default

The wrapper replaces the SDK's processMessage on the ChatInstance it hands the adapter, so messages reach chamvi's intake instead of the SDK's handlers and its pre-handler deduplication (which would drop a redelivery after a failure). Actions (processAction) are not supported.

Platform packages ​

ts
interface IChatPlatform {
    online?(): boolean;
    prepare?(input: ChatPlatformSend): ChatPlatformPost;
    conversationTarget?(incoming: ChatIncoming, payload: ChatPayload): ConversationTarget | undefined;
    sentMessageId?(send: { key: string }): string | undefined;
}
type ChatPlatformSend = { adapter: string; threadId: string; text: string; key: string };
type ChatPlatformPost = (signal: AbortSignal) => Promise<unknown>;
ts
// passed as chatChannel({ ..., platform }) by a platform package
export const platform: IChatPlatform = {
    // sends go out only while the client is connected
    online: () => client.connected,
    // the client posts itself, with a message id derived from the message key;
    // the signal aborts at the send's deadline or when the channel stops waiting
    prepare: ({
        threadId,
        text,
        key,
    }) => (signal) => client.send(threadId, text, key, signal),
    // the conversation of a message for an agent with `conversation`
    conversationTarget: (_incoming, payload) => ({
        account: 'team',
        chat: payload.threadId,
        audience: `room:${payload.channelId}`,
        text: payload.message.text,
    }),
};

A platform package builds its Chat, its wrapped adapter and a chatChannel() with the public options, and passes what only its transport knows as platform. Every hook is optional and called on the platform object; a missing one keeps the default. The channel checks it at construction (InvalidAgentDefinitionError for one that is no object, a hook that is no function, or a plain object with a key that is no hook; a class instance may keep state in its own fields). The socket lifecycle stays with connect/disconnect, the message policy with allowMessage/resolveInvoker.

HookRunsAnswers
online()Per send, after prepare, only while the channel is startedFalse refuses the send (chat_request, nothing posted). Default true
prepare(input)Per send, after the address decoded and the message rendered, before onlineA throw refuses the target (its error reaches the caller as is, nothing goes out); else the post (ChatPlatformPost) the channel calls once and waits for, bounded by timeoutMs and the send's signal. The post gets a signal that aborts at whichever comes first, so it can cancel its request; a failure is a chat_request, a late outcome goes to onError (not a rejection with that abort reason). key is ChannelMessage.key, the same on every retry. Default the adapter's postMessage(threadId, { raw: text })
conversationTarget(incoming, payload)Per agent with conversation, after allowMessage, the text checks and resolveInvoker (never for a refused message)The conversation identity; undefined refuses that agent's dispatch (chat_intake_failed, the other agents still run), a throw fails the message. sentMessageId({ key })With answers, per reply that quotes a messageThe platform's id of the message sent under key (the id prepare sends), so a quote matches its approval. Without it a quote never answers. WhatsApp has it; Discord has none (Discord assigns message ids)

Intake ​

Per message, in order: the bot's own messages are skipped; ids are checked (ValidationError, never echoing ids or text); allowMessage decides; a message with attachments or without text is refused (ValidationError to onError), except a voice message with voice; resolveInvoker; a voice message is transcribed (below); with answers, a reply that answers an approval stops here (below); then every agent with a matching subscription gets one run, through the engine's trusted conversation intake for an agent with conversation, else a plain dispatch. The idempotency key hashes channel, adapter, thread, sender and message id, so a redelivery dedupes per agent; a plain dispatch also gets a per-chat concurrency key. A transient failure (a store write) is retried after 1 s and 2 s; an agent already accepted is not dispatched again. What still fails is reported once as chat_intake_failed, naming channel, adapter and agents, never the text.

Webhooks ​

POST /channels/<name>/<adapter> (only adapters in webhooks, else 404) reads the body up to CHAT_BODY_LIMIT_BYTES (413 above it, before the adapter runs) and hands the raw request to the adapter's handleWebhook, which verifies it (its 401 passes through). The answer waits for every message the adapter handed over in the request's async context until each is stored as runs, at most CHAT_WEBHOOK_TIMEOUT_MS; a message that could not be stored for a reason a redelivery may fix (a store failure, the channel not started or stopping), or the timeout, answers 503 so the platform redelivers. A message only refused (attachments, no text, invalid ids, no conversation identity, a denied conversation, a throwing filter) is reported once and gets the adapter's own answer: a redelivery would be refused again. An adapter that passes messages to a consumer running in another async context (started before the request) is not tracked: its own 2xx stands. GET challenge flows are not served. The mount is under the http app's general rate limit unless channelRateLimits names the channel.

Subscriptions ​

ts
chat.on(options?: ChatSubscriptionOptions): ChannelSubscription<ChatPayload>; // channel 'chat'
channel.on(options?), channel.to({ adapter, threadId }): string;
// ChatSubscriptionOptions = { adapter?, events?, id?, filter?, concurrencyMaxRuns? }

events: direct, mention, message (any other group message), default DEFAULT_CHAT_EVENTS ['direct', 'mention']. id default chat:<events> (chat:<adapter>:<events> with an adapter). The payload, ChatPayload { adapter, event, threadId, channelId, message: { id, text, author: { id, name? }, sentAt? } }, holds no raw platform object. The run's address (chat: + base64url of [adapter, threadId], at most 255 characters) is the chat.

Outbound ​

emit() sends title, a blank line and body, refused above maxTextChars (default CHAT_TEXT_MAX_CHARS; no splitting). approve() sends the title and body (only this prose is cut, surrogate-safe), the options (- <id>: <label>, no detail), Expires: <ISO> and Approve or deny: <approvalUrl> (with options Choose and approve or deny: <approvalUrl>); the owner answers in the UI, or with answers by a reply, there are no native buttons. An approval answerable in the chat (answers, a direct chat as the adapter's isDM tells, no options, no trust-gate notice) is never cut: one that does not fit is refused before the run waits (the channel's fits), so the tool's approve() fails with a ValidationError; keep its title and body within the chat's limit. Other approvals (a group chat among them) are cut as without answers, with the link. ChannelMessage.slot is ignored: every message is a new chat message. A send is bounded by timeoutMs; a timeout fails with chat_request saying the message may still be delivered, a late completion is reported, and the engine's retry may send it again (at least once). A send while the channel is stopped or draining fails.

Answers in the chat ​

ts
type ChatAnswerOptions = { model?: ModelRef; timeoutMs?: number }; // default the approval's agent model, CHAT_ANSWER_TIMEOUT_MS

With answers, the owner can answer an approval by replying to it in a direct chat, in their own words and any language. A model reads the reply as approve, deny or unclear: by default the model of the approval's agent (else the app's), with no tools, seeing only the approval's title and the reply; a model failure or timeout counts as unclear and is reported to onError. An approval the chat can answer is sent to a direct chat, has no options and is no trust-gate notice; its message ends with CHAT_ANSWER_HINT (on a platform without quote matching CHAT_ANSWER_HINT_PLAIN) and needs no approvalUrl. A reply answers an approval only if it renders whole under the channel's current options (one that would be cut never answers). Raising maxTextChars or dropping approvalUrl can make an approval sent cut before the change answerable, so change those settings with no approvals open.

  • Who: only a direct message, whose invoker holds chamvi_agent_approve for the run's agent (checked before the model reads anything). The answer goes through engine.approve() with that invoker as approver.
  • Which approval: a reply quoting an approval message answers that approval (on platforms with sentMessageId, such as WhatsApp). A quote that names no open approval (any other message, or an approval no longer open) is an ordinary message. A quote without a usable id never answers. A reply without a quote answers the one open approval of the chat; with several open, the sender is asked to quote the one meant. Discord has no quote matching: a native Reply there never answers, a plain message only when exactly one approval is open, and with several open the sender is pointed to the dashboard.
  • When: only an approval that was delivered to the chat and has not expired, and only a reply sent at or after that delivery. The reply's send time comes from the platform and the delivery time from the server: clock skew between them errs towards not answering (the reply starts a run instead).
  • Once: a reply answers at most one approval, once; a redelivery of a reply that answered is dropped (no run). When the answer itself fails (a store failure), the reply's claim is released and a redelivery may answer; a failed release, or a crash between the claim and the answer, leaves the reply consumed (send a new message). An approval answered elsewhere in the meantime gets This approval is no longer open.
  • Waiting: while a run that started in a chat (or its conversation) waits on an approval, the same agent's next run there waits behind it (per-chat and per-conversation run concurrency), so a reply that does not answer starts a run that begins only once the approval is answered or expires.
  • Anything else (an unclear reply, a group message, a sender without the permission, a quote of an ordinary message) starts runs as usual. A store failure before the answer is reported to onError and the reply starts runs as usual.

Fixed answer words were rejected: the reply may be in any language. The agent's own model does not read it either, since an injected message could steer it.

Voice messages ​

ts
type ChatVoiceOptions = {
    model: TranscriptionModelRef; // '<provider>/<model id>' through the app's resolver, or a TranscriptionModel
    maxBytes?: number;   // CHAT_VOICE_MAX_BYTES
    maxSeconds?: number; // CHAT_VOICE_MAX_SECONDS
    timeoutMs?: number;  // CHAT_VOICE_TIMEOUT_MS, download and transcription together
    label?: string;      // CHAT_VOICE_LABEL
};

With voice, a message whose only attachment is one audio file the platform can download (fetchData; WhatsApp voice notes) is transcribed and then handled as a text message whose text is label plus the transcript: the agent, the conversation memory and answers see that text, so a spoken "yes" answers an approval like a typed one. The run's payload gets voice: { mediaType, bytes, seconds? }; the audio is held in memory only, never stored. The model must resolve when the channel starts (InvalidAgentDefinitionError fails the app start).

  • Policy first: nothing is downloaded before allowMessage allowed the message and resolveInvoker ran, and only when the note could go somewhere: a live agent subscribes to this channel for its adapter and event (the subscription's filter runs later, on the transcript), or, with answers, it is a direct message of an invoker. Otherwise it is refused like any attachment, without a notice.
  • Bounds: a reported duration above maxSeconds or size above maxBytes is refused before any download with Voice message too long: at most <N> minutes. (1 minute. for N = 1); a downloaded body above maxBytes, a failed download or transcription, an empty transcript or the timeout gets I could not understand the voice message. Each notice goes to the chat once per delivery (keyed by message, so a platform may drop a duplicate; nothing guarantees it, so a redelivery can post it again), the reason to onError (a failed download or model call as chat_request, a bound or an empty transcript as validation_error), and no run starts.
  • Download contract: the channel checks the downloaded size only after fetchData returned and cannot cancel it (it takes no signal; the timeout only abandons it). So maxBytes bounds memory only when the platform's fetchData bounds its own read to voice.maxBytes, as @chamvi/chat-whatsapp does; the Chat SDK's stock adapters download without a limit (which is why @chamvi/chat-discord removes theirs), so do not rely on it with such an adapter.
  • Concurrency: at most two voice messages per channel hold a slot (downloaded and transcribed) at once; others wait. A timed-out message releases its slot: its download is abandoned, not cancelled, and no longer counted, so a platform should bound its own download in time and bytes (@chamvi/chat-whatsapp aborts its fetch once the body passes maxBytes).
  • Without voice, an audio file the platform cannot download (Discord today), two attachments, or audio with anything else (typed text included) is refused like any other attachment.
  • Order: transcription takes seconds, so a typed message sent right after a voice note may start its run first; on WhatsApp, messages of the same batch behind a note wait for it.
  • Checks: the model resolves in the channel's start, so chamvi start --check does not report a bad voice.model; the app start does.

A platform sets the reported duration as durationSeconds on the attachment (ChatAudioAttachment).

Memory and trust ​

An agent with conversation is bound to { account, chat, audience }: audience direct:<author> for a direct chat, group:<channel> for a group (one memory per group). It needs the engine's conversationService and conversations: { authorize }; see Conversation Memory. Runs are tainted by default, so guardWhenTainted tools ask for approval; replies to the source chat and the defaultAddress are exempt from the outbound gate (see untrusted content).

ts
/** A reply on the channel `name`; on the run's source channel it answers the source chat. */
const replyOn = (name: string) => defineTool({
    description: 'Reply in the chat the message came from.',
    inputSchema: z.object({ text: z.string() }),
    execute: async ({ text }, { context }) => {
        // the source chat: no address, and no outbound gate in a tainted run
        await context.channels.findOneOrFail(name).emit({ body: text });

        return 'sent';
    },
});
const reply = replyOn('chat');

export const assistant = defineModelAgent({
    name: 'assistant',
    model,
    instructions: 'Answer with the reply tool.',
    // one memory per direct chat and one per group
    conversation: true,
    // direct messages and group mentions (events: ['direct', 'mention'])
    channels: [channel.on()],
    tools: { reply },
});

// runs, steps, checkpoints, effects, artifacts, state and conversations in memory, gone with the process: @chamvi/app keeps them in PostgreSQL
const registry = new MemoryRegistry();
const runs = new MemoryRunRepository({ registry });
const locks = new MemoryLockRepository({ registry });
export const engine = new Engine({
    runService: new RunService({ repository: runs, clock: systemClock }),
    stepService: new StepService({ repository: new MemoryStepRepository({ registry }) }),
    checkpointService: new CheckpointService({ repository: new MemoryCheckpointRepository({ registry }) }),
    effectService: new EffectService({ repository: new MemoryEffectRepository({ registry }) }),
    agentRevisionService: new AgentRevisionService({ repository: new MemoryAgentRevisionRepository({ registry }) }),
    artifactService: new ArtifactService({ repository: new MemoryArtifactRepository({ registry }) }),
    stateService: new StateService({
        repository: new MemoryStateRepository({ registry }),
        documentRepository: new MemoryStateDocumentRepository({ registry }),
    }),
    lockService: new LockService({ repository: locks, clock: systemClock }),
    idempotencyService: new IdempotencyService({ repository: new MemoryIdempotencyRepository({ registry }), clock: systemClock }),
    conversationService: new ConversationService({ repository: new MemoryConversationRepository({ registry }), clock: systemClock }),
    agents: [assistant],
    channels: [channel],
    conversations: { authorize: ({ agent }) => agent === 'assistant' },
});

chatModule ​

ts
function chatModule(options: { channel: ChatChannel }): IModule; // @chamvi/chat/module, name chamvi:channel:<name>
ts
export default createApp({
    agents: [assistant],
    modules: [chatModule({ channel })],
    conversations: { authorize: ({ agent }) => agent === 'assistant' },
});

Contributes the prebuilt channel to AppToken.CHANNELS; the engine starts and stops it, the http module mounts its in. No env variable, no start step; start --check neither initializes the Chat nor connects. A channel that is no chatChannel() is InvalidAgentDefinitionError.

Not supported yet ​

Media other than voice messages (incoming attachments, outbound files), spoken replies, platform history, message splitting, native approval buttons and actions, and verified webhook platforms beyond the generic adapter contract. For WhatsApp's own gaps see WhatsApp, for Discord's Discord.
