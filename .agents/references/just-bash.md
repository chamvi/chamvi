## Differences from real workspaces

The shell and commands run in the chamvi process. Default virtual files include synthetic command/proc entries; their bytes count toward filesystem limits. chamvi therefore adds a 65,536-byte synthetic reserve to twice `maxBytes`, preserving room for exact boundary-sized selected input and output. just-bash charges cumulative output before redirection and across pipeline stages, so interpreter work output has a separate finite allowance of `max(65_536, maxBytes * 4)` bytes. The decoded diagnostic display independently shares 65,536 UTF-8 bytes and can clip successful command output without failing execution. Aggregate artifact import/export caps remain exactly `maxBytes` each. No real `git`, `npm`, `node`, Python, SQL or archive executables exist in this command surface. There is no VM isolation or complete host-security boundary.

`@chamvi/coding` instead uses workspace providers and real programs, with run-scoped workspace lifecycle and retained shell state. Keep Docker/Kubernetes for builds, Git, tests and servers; do not implement `ISandboxProvider` with this interpreter. Execution budget exhaustion can return nonzero status/diagnostics rather than throw; chamvi exports nothing on nonzero exits, while unexpected infrastructure exceptions become `SandboxError`.

On upgrade, inspect the pinned declarations and bundled implementation for command registration (including nested `env`/`xargs`/`find` dispatch), filesystem initialization quotas and synthetic overhead, cumulative output accounting before redirection, output encoding and abort/limit behavior. Preserve real-wrapper coverage for ordinary 128 KiB redirection/pipelines, equal input/output boundaries (32 KiB and default 5 MiB), exact artifact overflow, bounded work/scratch exhaustion and visibly marked UTF-8 diagnostic clipping even when stderr fills the display budget. Run the real-interpreter and engine tests under `packages/tool-files/test/unit/tools/`, plus its executable README test. Confirm foreign-run ownership, byte limits, fresh-call state, taint, per-tool-call output identity and cancellation before publication. Native artifact writes remain nontransactional.

The 3.6.0 dependency tree pins `guarded-fetch@0.1.3` and `undici@7.29.0`; production `npm audit` reports advisories including [TLS option loss](https://github.com/advisories/GHSA-2m5v-pch6-74hx). Network commands and fetch configuration are unavailable through fileTools, so the affected HTTP/WebSocket paths are not offered here. This is an installed dependency risk, not evidence of an exploitable fileTools path. Recheck the published upstream tree on upgrade; a root-only npm override would not fix this package's consumers.
