# Knowledge

Read before changing `@chamvi/knowledge`.

Reference material an agent searches by meaning through an explicit tool, never put into the model context. The boundary (docs `guide/knowledge.md`, first section): a skill is followed (procedures, loaded whole by name), knowledge is looked up (facts, a few passages by meaning), conversation memory is what was said in one chat. Knowledge never contributes system instructions, never reads or writes conversation data and reuses no skills or memory vocabulary. Core gains no knowledge or vector concept; `@chamvi/store-db` is untouched; neither app nor test-kit depends on the package.

- **Embeddings**: `IModelResolver.embedding?(ref): EmbeddingModel` (core, optional, generic) is implemented by the app's resolver (`createModelResolver`: the same `providerOf(ref)` path as `resolve()`, so `models` overrides, unconfigured providers and missing packages behave alike; a throwing `embeddingModel(id)` becomes `Provider "<p>" offers no embedding model "<id>".`). The engine module registers its resolver as `AppToken.MODELS` in `setup` (start, job and check; nothing in migrate). A collection's stored model identity is the string ref, or `<provider>/<modelId>` for an object; vectors of two models never mix. Embedding is the AI SDK's `embedMany` (`maxRetries: 0`, the indexer's backoff retries), 64 values per call (`EMBED_BATCH_SIZE`).
- **Contract** (`IKnowledgeRepository`, `repository/types.ts`): collections (`saveCollection` upsert, `findOneCollection(OrFail)`, `findCollections` in code-point order, `deleteCollection` with its documents and chunks), documents (`saveDocument`, `findOneDocument(OrFail)`, `findDocumentIds`, `deleteDocument` with every generation's chunks), `replaceChunks(collection, document, generation, chunks)` (atomic per document and generation; `[]` removes them), `deleteGeneration`, `deleteGenerationsExcept(collection, generation)`, `search(collection, generation, vector, { topK, minScore? })` (cosine, descending, ties by document id then chunk index, joined with the document's `title`/`source`). Values copied in and out; `saveDocument`/`replaceChunks` of an unknown collection are `repository_not_found`; chunks may precede their document record (the indexer writes chunks first). `describeKnowledgeRepositoryContract()` (test-kit, structural types) runs every backend; `mockEmbeddingModel()` is a hashed bag of words.
- **Declared collections**: `knowledgeCollection(name, { model, sources, trusted? })` (agent-name rule, at least one source; `trusted` defaults to every source trusted), declared at app level only (`knowledgeModule({ collections })` or `createKnowledge({ collections })`); agents name what they search. `createKnowledge()` checks everything when called (`InvalidAgentDefinitionError`: a name twice, a string model without a resolver or one `embedding()` refuses, prefixed `Knowledge collection "<n>": `). Sources: `folder(path)` (Markdown and text, sorted; a walk one directory at a time that never enters a symbolic link (a link to a file or a directory is reported and skipped, so no escape or loop), dot entries skipped, an unlistable subdirectory, files over 1 MiB and non-UTF-8 files reported and skipped, `O_NOFOLLOW`; a path that is no directory fails its `check()`) and `defineKnowledgeSource()` (each yielded item checked, an invalid one reported by id and skipped; an optional `check()` kept). `IKnowledgeSource.check?()` validates configuration without reading documents; `IKnowledge.check()` runs every source's (prefixed with the collection), so a missing folder fails the boot and `start --check`. Chunker `text-v1` (`chunkText`): blank-line blocks packed greedily to 2000 characters, a heading kept with the next block, ~200 characters of word-aligned overlap, never a cut high surrogate; `contentHash` is `sha256:<hex>`.
- **Generations and sync** (`indexer/`, internal): a collection serves one `generation` (0 = never indexed) at one model and chunker; `pending` holds a re-embed's target. `syncCollection` writes into the served generation when it matches the definition, else into the matching pending one, else into a new one numbered past `lastGeneration` (a number is never given out twice: documents of an abandoned generation still name it), status `stale` while a generation is served, `pending` before the first; an unchanged hash at the target generation costs nothing (a restart with unchanged sources makes no embedding call); per changed document it chunks, embeds, renews the lock again (a lease lost while embedding ends the sync before any write), `replaceChunks`, then `saveDocument`; documents the sources do not yield any more are deleted, unless a source called `ctx.incomplete(reason)` (`folder()`: an unlistable subdirectory, a file read error; never a permanent skip): then nothing is deleted (reported once), and a re-embed fails with a `ValidationError` (retried on the backoff) instead of switching; a re-embed then switches the served generation (dropping the previous model's `dimensions`) and deletes the old one; a sync at the served generation deletes every other generation (`deleteGenerationsExcept`: an abandoned re-embed, or what a crash between a switch and its cleanup left). The record's `trusted` is written conservatively at the start (`stored.trusted && definition.trusted`: a downgrade at once) and the definition's value only in the final save, after the sources' documents were replaced and the stale ones deleted. Duplicate ids across sources keep the first. A `managed` record of a declared name is refused (`managedNameError()`); `check()` (read-only) refuses it at boot.
- **Lock and loop**: one loop per declared collection under the store lock `knowledge:<name>` (`KNOWLEDGE_LOCK_TTL_MS` 300 s, renewed by release and re-acquire after half of it; a lock another owner took ends the sync without an error). A loser (and a sync whose lock was lost) waits `KNOWLEDGE_RETRY_MS` 5 s on the `IClock` and tries the lock again, so every replica syncs its own sources once it is free (unchanged hashes embed nothing). A failure is stored on the declared record (still under the lock) with `failures` and `retryAt` (5 s doubling per failure in a row to `KNOWLEDGE_RETRY_MAX_MS` 300 s), reported through `onError(error, { collection })`; every replica's loop waits until `retryAt` before acquiring (re-checked after the acquire), except on its own first attempt, so the backoff is per collection, not per replica; a success clears both. A store failure that left no `retryAt` falls back to the loop's own backoff. An `InvalidAgentDefinitionError` (by code) is stored and reported once and ends the loop. Each indexing `embedMany` call is raced against `KNOWLEDGE_EMBED_TIMEOUT_MS` 60 s on the `IClock` (aborted, `ChamviError` `knowledge_request`), so a stalled provider is a reported, retried failure well inside the lock lease. A throwing `onError` is contained (`console.error`). `start()` also marks declared records without a definition `orphaned` (kept, searchable by no agent; a re-declared name re-syncs), each under its `knowledge:<name>` lock (held elsewhere: left alone) and re-read once held. `stop()` aborts and awaits every loop; a `start()` meanwhile begins once they settled. The default owner is `<hostname>-<pid>-<uuid>`, one per instance.
- **Search and taint** (`tools/`): `knowledgeTools({ collections, topK?, minScore? })` gives `knowledge_search({ query, collection?, topK? })`, a plain `defineTool()` reaching the knowledge through the context pair. A collection outside the options, and an orphaned or `declared` record this app does not declare, is refused before any read or embedding (an orphaned record of a name this app declares is served: an older replica of a rolling deploy may have marked it); a missing record or generation 0 is `ValidationError` `Knowledge collection "<n>" is not ready.` (never empty results). Every served model is resolved first through `IKnowledge.embedding()`; one that does not resolve is a `ValidationError` naming the collection (during a re-embed: `... is being re-embedded; its previous model "<id>" is not available here, ...`: an object model the definition dropped, or a removed provider, leaves the served generation unsearchable until the switch). The query is embedded once per model, each collection searched at its served generation, merged by score (ties: collection, document, chunk index), cut to `topK` (default 5, max 20) and at whole matches past 20 000 characters (`truncated`). `trust.taint` is a predicate: a search over any collection untrusted by its record or its declaration, or without a record unless this app declares it trusted (that one only answers "not ready"), taints the run `tool:knowledge_search`; the predicate's answer is kept per input object, and after the searches every record is read again: a changed `generation`, or a collection untrusted now that the call was not tainted for, is a `ValidationError` `Knowledge collection "<n>" changed while it was searched; search again.` instead of a result; checkpoints and replay apply as for any tool.
- **Module** (`/module`, `knowledgeModule({ collections?, repository?, owner? })`, name `chamvi:knowledge`, dependencies config, store, engine): options checked when called; `setup` (not in migrate) builds `createKnowledge()` over the repository (default memory, `MEMORY_KNOWLEDGE_WARNING` outside dev), `AppToken.STORE.locks`, `AppToken.MODELS`, `AppToken.CLOCK` and the logger (`knowledge error` with `collection`); a configuration error fails the setup. `onReady` runs `check()` (also in a check). The lifecycle hook provides the context in `engineCreated` and, in start mode outside a check only, `started` runs `start()` and `stopping` awaits `stop()`; `teardown` stops too. A job or a check never indexes. Phase 2 (managed collections over REST) and phase 3 (`@chamvi/store-db-vector`, pgvector with its own migrations) follow.
- **Downstream contract**: phase 1 adds no env variable, CLI change, route or port; `AppToken.MODELS` is additive public `@chamvi/app` API that neither chamvi/helm nor chamvi/agent-template uses, so it needs no downstream change. Phase 2's managed default `CHAMVI_KNOWLEDGE_MODEL` (and its REST routes under `/knowledge`) is a downstream contract change: it needs a PR in both repositories (helm values/env, the template's `.env.example` and docs) when it lands.

## Testing

- `@chamvi/knowledge` tests never reach an embedding provider: `mockEmbeddingModel()` from `@chamvi/test-kit` is a hashed bag of words (64 dimensions by default, normalized; `calls` records every `doEmbed` call's values). The memory repository runs `describeKnowledgeRepositoryContract()` (`test/unit/repository/memory.spec.ts`), which every knowledge backend must pass. `test/utils/indexer.ts` holds `createIndexerSetup()` (a `ControllableClock`, a memory repository, recording locks over `createMemoryStore().locks`, collected `onError` calls), `mapSource()` (a source over a mutable map), `embeddingResolver()`, `gatedModel()` (embedding calls that block until opened, rejecting on abort), `waitForCollection()`/`waitForReady()`; `test/utils/tools.ts` holds `toolContext()` (a `ToolContext` with the knowledge bound as the engine would), `callTool()` and `seedCollection()` (a record with documents and chunks written straight into the repository). Indexer timing (backoff, lock renewal, the embed timeout) is driven by advancing the `ControllableClock`; tests that move the clock past `KNOWLEDGE_EMBED_TIMEOUT_MS` while an embedding call is open hold the source between documents instead. The trust regressions drive a real `Engine` with `mockModel` (`test/unit/tools/trust.spec.ts`); the module spec runs on `buildModuleHarness()`/`createModuleHarness()` from `@chamvi/app/testing` and asserts the registered `chamvi:knowledge` lifecycle hook instead of waiting on real timers. The folder specs use real temporary directories (symbolic links, a `chmod 000` subdirectory, skipped as root).
