# Cron Channel

Read before changing `@chamvi/channel-cron`.

`@chamvi/channel-cron` is the cron channel; it depends on `hubwire` (croner inside) and `cron-parser` and is a peer of core.

- `cron.on(expression, { timezone?, overlap?, payload?, id?, conversation?, text? })` (`subscription/`) makes a subscription of the channel named `cron` (id default `cron:<expression>`); it validates the expression with cron-parser, the timezone with `Intl`, the overlap policy (default `skip`; `queue-one`, `allow`), a non-empty `id`, and `conversation` (core `ConversationRef`) and `text` both or neither, non-blank (`readCronConversation()`, `InvalidAgentDefinitionError`). Scheduling and `runJob()` refuse a ref to a channel the engine lacks, `readCronOptions()` one on an agent without `conversation`. `cronChannel({ name?, owner?, lockTtlMs?, onError? })` (`channel/`) is the channel; its `on()` makes subscriptions only it fires (a second instance, e.g. `cron-eu`), and `cron.on()` ones reach only the channel named `cron`.
- `start(ctx)` runs the internal `createScheduler()`, which builds one hubwire `defineScheduledComponent` per cron subscription of this channel in `engine.listAgents()`, named `cron:<agent>:<subscriptionId>`, with `lock: createRepositoryScheduleLock(engine.store.locks, owner)` (`ILockRepository.acquire`, never released) and `lockTtlMs` default `SCHEDULE_LOCK_TTL_MS` (10 min). hubwire's tick key is `${name}:${scheduledAt ISO}`. The subscription of an agent without a revision (one passed in code) hubwire refuses (expression croner rejects, timezone) throws `InvalidAgentDefinitionError` out of `engine.start()`; a folder agent's (registered at a revision) goes to `onError` and leaves it unscheduled. `assertSchedulable(agent, channel?)` is the same check without scheduling (the app's `AGENT_CHECKS`).
- Live components: the channel keeps its components per agent (`buildAgentComponents()`, `scheduler/helpers.ts`) and follows `agents.changed`: `added` builds and starts the agent's components, `replaced` stops the old ones and builds the new, `removed` stops them. A replacement hubwire refuses goes to `onError` and leaves the agent unscheduled (never a throw). Retired components stop in the background; `stop()` (called first by `engine.drain()`/`stop()`) unsubscribes, stops every component and awaits their `settled()` plus the retired ones.
- `runOnStart: false` always: a start pass never takes hubwire's lock and would fire on every replica. hubwire skips a locked tick fired `lockTtlMs` or more late; `onSkip` is not wired (N - 1 replicas skip every tick). Lock, overlap and dispatch failures reach `onError(error, { agent, subscription })`.
- `fireCronSubscription({ engine, agent, subscription, scheduledAt })` is one tick: overlap check (over `engine.store`), then `dispatch` with `channel` the subscription's channel, payload `options.payload ?? { scheduledAt: ISO }`, idempotency key `<subscriptionId>@<scheduledAt ISO>` (the subscription's own `idempotencyKey()` is ignored), `concurrencyKey = subscription.concurrencyKey?.(payload) ?? (overlap === 'allow' ? undefined : subscription.id)`. With a `conversation`: the same key and payload through the ref channel's `channelContext().dispatchConversation(envelope, { account, chat, audience, text })`, address the ref's, no concurrency key (the intake sets the conversation's and refuses another: never the subscription id). Replies to that source need no tainted-outbound approval and become turns; `authorize` sees no invoker and a refusal rejects (`onError`); a missing channel answers `reason: 'channel'`.
- Overlap: active runs are `queued | running | waiting | interrupted` of the agent filtered by `run.trigger.trigger`. `skip` skips while any is active, `queue-one` while one is `queued`, `allow` never. The check-then-dispatch race is made harmless by the default concurrency key (the extra run waits).
- `runJob({ engine, agent, subscription?, pollMs?, drainTimeoutMs?, signal? })` prepares the engine's skills (`engine.prepare({ signal })`: a failure rejects before any dispatch, an abort meanwhile answers `skipped`), fires once at `engine.clock.now()` (the engine must hold the subscription's cron channel), then always starts the engine with `start({ channels: false })` (a job never starts cron schedules or sockets) and calls `engine.tick()` once (so a skipped tick still recovers leftovers of earlier jobs and times out expired approvals), waits via `run.updated` plus an `engine.getRun` poll (`pollMs`, default 1 s, covers another replica) for `completed | failed | cancelled`, an approval wait of the run or a descendant (`isJobSettled` over core's `findApprovalWaitBelow()`, `waitingRunId` the descendant; a dispatch wait alone keeps the job waiting, #129), or for `queued` behind a run of the same concurrency key waiting on an approval (`queue-one`), then `drain({ timeoutMs })` (default 30 s). Exit code 1 for `failed`/`cancelled`, else 0; an overlap skip returns `skipped` after the drain. It starts a full engine over the shared store (every queued run of every agent), so size the drain timeout. `signal` (the CLI's SIGTERM): aborted before the call, nothing fires or starts (`skipped`); during the dispatch, the engine never starts (`queued`, exit 0); re-checked after `engine.start()` (skips the approval tick); while waiting, the wait ends and the drain runs (`interrupted`, exit 0).

## Module map

| Path | Purpose |
|------|---------|
| `channel/` | `cronChannel()` (`module.ts`), `CronChannel`, `CronChannelOptions`, `CronChannelErrorContext` (`types.ts`), `CRON_CHANNEL_NAME` (`constants.ts`), `markCronChannel()`, `isCronChannel()`, `assertCronChannelOptions()` (`asserts.ts`, internal) |
| `subscription/` | `cron` (`cron.on()`, the only export) and `createCronSubscription()` (`module.ts`, cron-parser and timezone validation), `readCronConversation()` (`helpers.ts`, internal), `OverlapPolicy`, `CronSubscriptionOptions`, `CronSubscriber` (`types.ts`), `OVERLAP_POLICIES` (`constants.ts`) |
| `lock/` | `createRepositoryScheduleLock()`: hubwire `IScheduleLock` over core's `ILockRepository` |
| `tick/` | `fireCronSubscription()` (overlap check, envelope, dispatch), `readCronOptions()`; `isOverlapping()` in `helpers.ts` |
| `scheduler/` | `createScheduler()` (internal, the channel's engine), `assertSchedulable()` (public), `SCHEDULE_LOCK_TTL_MS`; `buildComponentOptions()`, `cronSubscriptionsOf()`, `buildAgentComponents()`, `toDefinitionError()`, `assertConversationChannel()` (`helpers.ts`, internal) |
| `run-job/` | `runJob()`; `resolveCronSubscription()`, `isQueuedBehindApproval()` (`helpers.ts`), `SETTLING` (`constants.ts`), both internal |

## Testing

- hubwire (croner) takes no `IClock`. Cron tick logic (`@chamvi/channel-cron`) is tested by calling `fireCronSubscription` or `buildComponentOptions(...).run({ scheduledAt })` directly; only tests that need hubwire to fire use `vi.useFakeTimers()` (always restored in `afterEach`), with in-memory repositories from `createMemoryStore()` on the default `systemClock`, which follows the faked `Date`. `packages/channel-cron/test/unit/hubwire.spec.ts` pins the upstream contract (lock, `scheduledAt`, timezone, DST, the expression croner and cron-parser disagree on).
