# Channels, Envelope and Dispatch

Read before changing `IChannel`, subscriptions, outbound handles, dispatch, the trigger envelope or execution ceilings.

## Channels and the envelope

A channel (`channel/`) is anything a run comes from or talks to; the presence of `start`, `in` and `out` is its only capability:

```ts
interface IChannel<TInput = ChannelRequest, TOutput = Response> {
    readonly name: string;                       // agent-name rules; unique per engine
    readonly defaultAddress?: string;            // emit()/approve() target without an address off the source channel
    start?(ctx: ChannelContext): Promise<void>;  // background intake (cron ticks, sockets, polling)
    stop?(): Promise<void>;
    in?(input: TInput, ctx: ChannelContext): Promise<TOutput>;  // HTTP: { request, subpath }, the raw Request and the raw subpath
    out?(message: ChannelMessage, address: string, opts: ChannelSendOptions): Promise<void>; // idempotent on message.key
}
// Engine.channelContext(channel) binds dispatch and dispatchConversation to the exact registered channel.
// ChannelMessage { kind: 'message' | 'approval', key, runId, agent, title?, body, approvalId?, expiresAt?, options?, multiple? }
// ChannelSendOptions { signal, trigger }: trigger = the run's stored envelope, read only
```

- **Lifecycle**: `EngineOptions.channels: IChannel[]`. `engine.start()` calls every `start(ctx)` after the first `recover()`, sequentially in registration order; a throwing `start` stops the channels already started and rejects `start()`. `engine.start({ channels: false })` starts none (`runJob()`). `stop()` stops the poll and every started channel (`Promise.allSettled`, rejections to `onError`) and returns that promise, so a caller can wait for the channel stops (cron ticks in flight) before closing the store; `drain()` awaits it **first**, then drains. A non-empty `defaultAddress` is checked in the constructor (`assertDefaultAddress`, `InvalidAgentDefinitionError`).
- **Trusted intake**: `Engine.channelContext(channel)` checks the exact registered object and returns engine-owned dispatch closures; startup uses the same path. Conversation validation lives in protected `intakeConversation()`, not a module-global callback registry or standalone dispatcher. `conversation/context.ts` holds only execution-bound trusted metadata; its weak map is separate from intake wiring.
- **Subscriptions** replace trigger definitions: `ChannelSubscription { channel, id, options, concurrencyKey?(p), idempotencyKey?(p) }` on `AgentDefinition.channels`. Each channel package exports a builder named after its default channel whose `on()` makes pure-data subscriptions (`cron.on()` in `@chamvi/channel-cron`, `http.on()`/`webhook.on()` in `@chamvi/http`, `github.on()` in `@chamvi/github`), and the channel factory's instance has `on()` bound to its own name (a second instance). Channels read their subscriptions from `ctx.engine.listAgents()` and follow `agents.changed`.
- **Outbound is tool-driven**: the engine never sends a message of its own, except the approval requests a tool asked for (see [Approvals and hooks](approvals.md)). `ctx.channels` (`ToolChannels`, built per execution by `createToolChannels()`, `channel/helpers.ts`, over `engine.getChannel()`/`listChannels()`) hands out run-bound `ChannelHandle { name, address?, emit, approve }`s for channels with `out`: `findOne(name?)` the channel `name` (default the run's `trigger.channel`) or `undefined` when the engine has none of that name or it has no `out`; `findOneOrFail(name?)` the same or `ChannelNotFoundError` (`channel_not_found`, naming the channel only); `find()` every channel with `out` in registration order. A handle on the source channel is bound to `trigger.address`. `emit({ title?, body, key? }, address?)` and `approve({ ..., address? })` default to the source address on the source channel, else to the channel's `defaultAddress` (`consoleChannel()` its name, `openclawChannel()` its `deliver.to`), else need one (`ValidationError` tool error); `emit` and is an effect (`createChannelHandle`, `channel/helpers.ts`): key `<runId>:emit:<channel>:<sha256 of address and canonical message>` (or `key`), recorded through `IEffectRepository` like `wrapToolsForRun`, and passed to `out` as `message.key`, so identical emits of one step and a step redone after a crash send once; a throwing `out` records nothing and is a tool error. Outside a tool call (the tools factory) `emit` throws `InvalidRunStateError`.
- `consoleChannel({ name?, write? })` (`channel/console.ts`): out only, default name `console` (also its `defaultAddress`), one header line `[chamvi] <kind>: <title ?? the body's first line> (agent <a>, run <r>, key <k>)`, the body lines, for an approval with options `select one:` (or `select one or more:`) and an `option <id>: <label>` line per option, then `approval <approvalId> waits until <ISO>`; never throws.
- **Dispatch** (`dispatch/`, #129, folds in #76): `dispatch(ctx, { role?, payload, idempotencyKey?, concurrencyKey?, address?, source? })` starts a run of the calling run's own agent, `dispatchTo(ctx, { agent, ...same })` of any registered agent (the own agent behaves exactly as `dispatch`), both resolving `DispatchResult { runId, deduplicated }` (free functions like `approve(ctx)`, `ToolContext` unchanged). The opt-in is a role: `agent.on({ role?, schema?, maxPerRun?, from?, maxDepth?, concurrencyMaxRuns?, idempotencyKey?(p), concurrencyKey?(p), address?(p), description? })` (channel `agent` = `AGENT_CHANNEL_NAME`, id = the role, default `DEFAULT_DISPATCH_ROLE` `default`, following the channel-name rule). Role ids share the agent's subscription-id namespace (`http`, cron and webhook ids): `defineModelAgent()` refuses duplicates and admission matches `concurrencyMaxRuns` by `id` alone, so they must stay unique. `maxPerRun` (default 100) is counted per run, agent and role; `maxDepth` 1 to `DISPATCH_DEPTH_MAX` 8 (default 1, a root run has depth 0); `from` lists the other agents that may dispatch to the role (the own agent always may); all checked by `agent.on()`, by `assertDispatchRoles()` in `assertRegistrable` (hand-built subscriptions too) and per call. `agentChannel()` (`channel/agent.ts`: name only, no `start`/`in`/`out`) serves them; a bare `Engine` lists it, `@chamvi/app`'s engine module contributes it.
- **Generated tools** (#131, `dispatch/tools.ts`, `bind.ts`, `schema.ts`): `dispatchTools({ roles?, agents?, wait? })` returns placeholders tagged with the internal `DISPATCH_TOOL` symbol (`dispatch_<role>`, `dispatch_<agent>_<role>`; names never collide since agent and role names have no `_`; at most 64 characters; `wait` changes the tool, never adds a `_wait` one, whose name would collide with the cross-agent form). `assembleTools` binds them per execution from the live registry (`bindDispatchTools`, converted input cached per agent object and role, so a `putAgent` replacement converts again): an object-root role schema is the input, any other root or none `{ payload }` (`$ref`s rebased); an unconvertible schema is `InvalidAgentDefinitionError` (never `{}`, unlike MCP's fallback). The validator checks with the role schema but passes the raw input on, so `dispatch()` parses once (a transform is not applied twice). The call passes no keys or address (the role hooks decide); `address(p)` feeds the dispatch's `callHash` and default key, so it must be deterministic. Classified `{ taint: false, guardWhenTainted: false }` (an internal destination; the child inherits taint). A placeholder whose name a state or skill tool carries is refused (`assertNoDispatchCollision`); an unregistered target keeps an untyped tool whose call is dispatch()'s `ValidationError`.
- **Lineage**: the engine provides the internal `DispatchHost { getAgent, effects, runs, clock, createRun(envelope, parent), serial(runId, fn), inflight }` under `DISPATCH_CONTEXT` (key `dispatch`, not exported). `createRun` is the only path that sets `trigger.parent = { kind: 'dispatch', runId, agent, role, depth }`; `engine.dispatch()` and `ChannelContext.dispatch()` strip a `parent` any caller passes, so lineage is never forged. The repository derives `Run.parentRunId` from it at `insert` (indexed; `find({ parentRunId })` lists children). A child inherits the parent's taint and invoker snapshot (never widened). The run's id, agent, invoker and parent come from the frozen copy bound per execution (`bindRunSnapshot()`/`runSnapshotOf()`, `dispatch/helpers.ts`), never from `ctx.run`.
- **Order per call** (every refusal a `ValidationError` tool error before any write): a tool frame (`InvalidRunStateError`), the snapshot, the input (`payload` required, keys non-empty without NUL, concurrency key and address at most 255), the target registered, the role (`Agent "<a>" has no dispatch role "<r>": add agent.on({ role: '<r>' }) to its channels.`), `from` for another agent (`Agent "<target>" role "<r>" accepts no dispatches from agent "<caller>".`), the invoker for another agent (`can(invoker, chamvi_agent_run, { attributes: { name, private }, now: host.clock.now() })`, `The run's invoker may not run agent "<target>" (chamvi_agent_run).`; a run without invoker passes), depth, the schema (the parsed value is the payload), no ancestor-key refusal: a child under the agent and key a run up the lineage holds is accepted and queues until that run settled (fire and forget, the hand-off sequencing the reviewer relies on); `waitForDispatch()` refuses to wait on it while that run still holds the key (`findKeyHolder`: running, waiting or interrupted; a settled ancestor holds nothing; the children are read again after the ancestor reads, so a child that settled meanwhile ends the wait). Then the effect lookup, and under `serial(runId)` the subtree budget (`BudgetExceededError` once the caller or an ancestor reached its agent's `budget.maxSubtreeTokens`, a new call only; the chain's totals summed from `find({ parentRunId })` per run, the run below with its fresh sum, the stored `subtreeUsage` when larger) and the count.
- **Keys**: idempotency key the input's, else `idempotencyKey(payload)`, else `<runId>:<stableHash({ agent, role, payload, concurrencyKey, address })>`, claimed as `dispatch:<role>:<key>` (`sha256:<hex>` above 255, `claimKey()`; the roles of one agent share its claim scope); a given key is not run-scoped, so a second run dispatching it gets the first child (`deduplicated: true`), but a dedupe into the caller or a run up its lineage is a `ValidationError` (a wait cycle); two runs of different subtrees deduplicating into each other are not refused: their waits only expire (both `timeout`, neither cancels the other). Effect `<runId>:dispatch:<callHash>` (an in-flight identical call shares its promise, a recorded call returns the record); count `dispatch-count:<runId>:<agent>:<role>` (`{ count, calls }`, written before the dispatch, so a crash spends the slot once and a call already in `calls` redoes the deduplicating dispatch); every dispatch (deduplicated too) appends the child id to `dispatch-children:<runId>` (`{ runIds }`, effects have no prefix listing). A failing children or call record is logged, the call still resolves.
- **Waiting**: `waitForDispatch(ctx, run | runs, { timeoutMs? })` (`dispatch/wait.ts`) takes ids or results the run owns (`parentRunId` is the run, or listed in `dispatch-children`; else `ValidationError` `Run <id> was not dispatched by run <runId>.`), one in one out, a list in its order (duplicates kept, `[]` at once). Settled runs resolve at once; otherwise the call suspends like `approve()` (its own ordinal `frame.waits`, wait id `<stepIndex>:<toolCallId>:w<n>`, never colliding with approval ids) and `pause()` writes a `DispatchWaitPoint { kind: 'dispatch', id, toolName, toolCallId, runIds, expiresAt }` (default `DEFAULT_DISPATCH_WAIT_TIMEOUT_MS` 24 h, 1 to `APPROVAL_TIMEOUT_MAX_MS`). Outcomes `DispatchOutcome { runId, agent, role, status: completed | failed | cancelled | timeout, output?, error? }` are recorded under `dispatch-wait:<runId>:<waitId>`; the call replays and returns them, after `markUntrusted(ctx, 'dispatch:<childId>')` for the first tainted child. The `wait` step holds the outcomes without `output`.
- **Resume** (`engine/dispatch/module.ts`): `onRunSettled()` runs after every terminal write (`finish`, `cancelStored`; best effort, errors to `onError`): recompute `subtreeUsage` up the lineage (a sum over `find({ parentRunId })` of `usage + subtreeUsage`, never an increment, patched with `keepUpdatedAt`, after the write the children that may still move (unsettled, or with a `subtreeUsage` of their own) re-read by `ids` and the total rewritten while it changed (`SUBTREE_RECHECKS` 3), so an interleaved sibling settle never leaves the stale total last; none of them (settled leaves) skips the re-check), cascade a cancel to the run's own unsettled children (awaited or fire and forget; a completed or failed parent leaves them running), then `answerDispatchWait()` on the parent. `pause()` re-checks the children after its write (a child that settled before it landed found no wait point). `tick()` heals: it expires waits past `expiresAt` (cancels listed unsettled runs the parent owns with code `Timeout`; a child that only got `cancelRequested` holds the answer until it settles (its push answers), at most `claimTtlMs` past `expiresAt`, then reads `timeout`; `cancelled` only for a re-read that shows it settled; runs owned elsewhere, reached through a shared key, get `status: 'timeout'` and keep running) and answers every wait whose runs all settled (lost push, another replica, a deduplicated child whose `parentRunId` names another run); it never delivers or denies a dispatch wait. `tick()` also heals a lost cascade (`healCancelCascade`, skipped while no registered agent declares an `agent.on()` role: one `find` of unsettled runs with `hasParent`, one batched read of their parents; cancels each one whose parent is `cancelled` and that has no `cancelRequested` yet). Every answer goes through `resume()` guarded by `expectStatus` and `expectWaitId`, so a push, a heal and a second replica answer once.
- The child's outbound names its channel (`agent` has no `out`, so `findOne()` without a name is `undefined`); `address` becomes `trigger.address`/`Run.address`. Under `runJob()` the drain interrupts children the job's engine picked up; recovery requeues them.

```ts
type TriggerEnvelope = {
    id: string;              // defaults to a UUID
    agent: string;
    trigger: string;         // the subscription id, e.g. 'http'
    channel: string;         // the channel the run came from, e.g. 'mcp'
    payload: unknown;
    idempotencyKey?: string;
    concurrencyKey?: string;
    address?: string;        // where the run came from on that channel (an issue, a thread, a caller); also Run.address
    attachments?: Artifact[];
    invoker?: Invoker;       // { id, kind, name?, bindings, identity? }, from an authenticator only
    parent?: TriggerParent;  // { kind: 'dispatch', runId, agent, role, depth }: set only by dispatch()/dispatchTo(), dropped from any engine.dispatch()
    receivedAt: Date;        // defaults to now
};
```

Envelopes stored by older releases have `source` and `thread`; `normalizeEnvelope()` (`trigger/helpers.ts`, public, used by both store mappers) fills `channel` from `source` and `address` from `thread` when absent and drops both legacy keys (`Run.address` reads the existing `thread` column; no migration).

`dispatch` validates a given invoker (non-empty `id` and `kind`, `bindings` an array of permission bindings, `identity` of type `user`/`client` with an `id`, `ValidationError` before any write) and stores a deep copy (`structuredClone`) of only those fields; a stored invoker is never re-validated on read, so old string entries grant nothing. It is a snapshot (identity and grants, never a token): a run paused on an approval keeps it, and revoking a grant does not reach a run that holds it. The idempotency scope includes the invoker (see Intake), so a deduplicated dispatch always comes from the invoker of the run it returns. Tool code reads it as `context.run.trigger.invoker` (tools and the factory's `run`) and `ctx.run.trigger.invoker` (effect hooks, agent hooks).

The envelope (channel, trigger, payload) is rendered as a JSON block and becomes the run's first user message: string content, or with attachments `[{ type: 'text', text }, ...one file part per attachment]` whose `data` is the marker `chamvi-artifact:<id>` (`ARTIFACT_URI_PREFIX`, internal). `TriggerEnvelope.attachments?: Artifact[]` holds their metadata; `DispatchEnvelope.attachments?: ArtifactInput[]` takes the bytes.

## Execution ceilings and channel HTTP policies

`AgentDefinition.concurrencyMaxRuns?: number | false` and `ChannelSubscription.concurrencyMaxRuns?: number | false` are nested shared-store execution ceilings; all subscription builders (`http`, `webhook`, `github`, `cron`, `agent` and named channel instances) forward the setting. `assertConcurrencyMaxRuns()` (`channel/concurrency.ts`, public) accepts undefined/false or a positive safe integer, else `InvalidAgentDefinitionError`; `defineModelAgent()` and engine registration validate both levels, including hand-built definitions. `false` removes only that level's numerical ceiling. `EngineOptions.concurrencyMaxRuns`/`CHAMVI_MAX_CONCURRENT_RUNS` stays engine-local. Renaming the pre-existing TypeScript engine option to `concurrencyMaxRuns` is breaking; the environment variable is unchanged.

`engine/queue/admission.ts` reads live definitions through `RunQueueOptions.getAgent` (like `Engine.getAgent`, a synchronous registered-agent lookup returning undefined when absent, without loading, creation or I/O); an agent with any numerical cap uses `admission:<agent>` with a fresh UUID owner and `claimTtlMs` lease around count, claim and queued-to-running transition (status and owner guarded), including starts of uncapped siblings. Agent counts include every running run; subscription counts match `run.trigger.trigger`, not `channel` (HTTP and MCP share `http`). A direct dispatch without a matching subscription takes only the agent ceiling. Uncapped agents skip the admission count path. Cancellation bypasses numerical blocking. The existing concurrency-key lock nests inside admission; release/reporting failures cannot discard a transitioned run before launch, even with a throwing `onError`. Guarantees require compatible replica definitions and critical-section store operations finishing inside the lock TTL. Waiting/interrupted runs consume no numerical capacity but keep their concurrency keys. Queued runs are scanned FIFO with blocked work bypassed, not weighted fairness; backlog is durable and storage-unbounded. No caps are stored in envelopes and no migration or broker is added.

`HttpAppOptions.channelRateLimits?: Record<string, false | ChannelRateLimitOptions>` (`app/types.ts`, public; policy `{ max, windowMs? }`) is forwarded unchanged by `httpModule()`. `plugins/channels.ts` validates exact mounted input-channel names, a positive safe `max` and a positive timer-safe `windowMs` (default 60 s); `InvalidAgentDefinitionError` before serving. Omitted entries retain the general shared per-client bucket; explicit policies replace it with a separate per-channel/client bucket, also with `rateLimit: false`; `false` skips only that mounted POST endpoint and subpaths, never unknown paths or other methods. Buckets are HTTP-app-local, not distributed run-store state. Matching respects normalized basePath, case and path boundaries. JSON 429, CORS, Retry-After and rate headers remain; IP lookup uses the app's trusted-proxy configuration, not the limiter library's permissive default. Signatures/auth/body caps are unchanged. No new env variable. A 202 acknowledges stored acceptance, not execution. GitHub does not automatically redeliver failed deliveries. Operators configure known ingress sources in app `trustProxy`; chart ingress settings do not do so automatically.
