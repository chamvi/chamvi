# Store and Database

Read before changing a repository contract, the memory store or `@chamvi/store-db` (entities, migrations, conversations on Postgres).

The contract itself (the `IStore` capabilities, the rules every implementation keeps, `findOne`/`find`/`OrFail`) is in architecture.md → *Repository Contract*.

`createDatabaseStore()` (`@chamvi/store-db`) assembles separate `Database*Repository` classes on one PostgreSQL DataSource, including conversations. Every method goes through the entities' repositories and query builders; the only hand-written SQL fragments are the `jsonb_exists` key check in `findDocuments` (TypeORM has no key-existence operator) conversation recall's `octet_length` byte bound and `update`'s `expectWaitId` condition `COALESCE(waiting->>'id', waiting->>'approvalId') = :waitId` (no `->>` in the ORM), containment uses `JsonContains`; `repository/helpers.ts` maps entities to `Run`, `Step` and `Checkpoint` (a `RETURNING` row is hydrated through the entity metadata). The listed run, artifact, idempotency, lock and checkpoint atomic operations each use one statement: `insert().orIgnore()` returning `id` (`runs.insert`; `artifacts.insert` with no conflict target, so a taken id and a taken `(run_id, key)` both keep the stored row), `insert().orUpdate()` on the conflict target `(run_id, key)` overwriting only media type, filename, size and bytes, returning the metadata (`artifacts.save`; the stored `id`, `agent` and `created_at` stay), `insert().orUpdate()` with the overwrite condition `expires_at <= now` returning a row (`idempotency.claim`, `locks.acquire`), a conditional `update()` (`claim`, `renewClaim`, the `update` guards, the latter returning `*`) and `insert().orUpdate()` with the overwrite condition `step_index <=` (`save`). Conversation operations instead use transactions and a `FOR NO KEY UPDATE` lock on the conversation row (never deleted, key never changed, so child-row foreign key `KEY SHARE` locks do not conflict) to serialize ownership and journal changes; a reset with `keepNotes` drops expired notes in both stores. Time comes from the `IClock` as a parameter, never the database's `now()`. Values are `jsonb` through column transformers (`entities/constants.ts`): the Postgres driver writes `JSON.stringify` and turns `null` into SQL `NULL`, so the transformers hand it a `toJSON` wrapper carrying the sanitized value (NUL and lone surrogates become U+FFFD); `JSON_VALUE_TRANSFORMER` (state, docs, effects, checkpoint messages) keeps `null` as JSON `null`, `OPTIONAL_JSON_TRANSFORMER` (run and step columns) stores it as SQL `NULL`. `trigger.receivedAt`, `trigger.attachments[].createdAt`, `waiting.expiresAt`, `waiting.notifiedAt` and `taint.at` are revived as `Date`. Only the latest checkpoint is kept. Every table has one `id` primary key: uuid v7 (generated by the `uuidv7` package, because Node's `crypto.randomUUIDv7()` is not ordered within a millisecond and `artifacts.find` and attachment order depend on it), bigint increment on `chamvi_steps` and `chamvi_conversation_items` (append-only, order across writers is the point; `id` stays a string at the boundaries). The natural identity of a row is a unique key: runs have none beyond `id`, keyed artifacts `(run_id, key)` (unkeyed ones only `id`), checkpoints `run_id`, idempotency keys `(scope, key)`, locks and effects `key`, kv `(agent, key)` (`key` `COLLATE "C"`, so `find` orders by code point), docs `(agent, collection, document_id)` (the domain's document id is `document_id`), agent revisions `agent`, connections `name`, connection entries `(connection_id, key)` (FK `ON DELETE CASCADE`), conversations `key` (the sha256 of the identity), items `(scope_id, generation, key)`, notes `(scope_id, generation, key)`, operations `(scope_id, generation, operation_id)`. An upsert's conflict target is that key and `id` is not overwritten. Every text column of these unique keys and every sorted text column is `COLLATE "C"`, so byte order holds whatever the database locale; the alpine test image sorts bytewise anyway, so a missing one shows only in `migrate.spec.ts`. A value that is not a uuid (`isUuid()`) is "not found" in `findOne`, `read`, `find({ ids })` and the run-reference paths and never reaches Postgres (`22P02`). Conversation scope ids: the memory store keeps the identity sha256, Postgres uses the row's uuid v7; core treats them as opaque strings. Artifacts live in `chamvi_artifacts` (`ArtifactEntity`: private nullable `key` (`select: false`, never in the domain artifact; `(run_id, key)` unique), `run_id` indexed with no foreign key because attachments are stored before the run exists, `agent`, `media_type`, `filename` nullable, `size` int, `data` `bytea` with `select: false`, `created_at` timestamptz). Markers live in `chamvi_agent_revisions` (`AgentRevisionEntity`: `agent` varchar(64) `COLLATE "C"` unique, `hash` varchar(128), `changed_at` timestamptz), `save` a repository `upsert` on `agent` (no compare needed: the engine holds `agents:<name>`), `find` ordered by `agent`; `findOne`/`find` never load `data`, `read` returns a plain `Uint8Array`. `migrateStore(dataSource)` runs the migrations under the advisory lock `chamvi:migrations`; `pendingMigrations(dataSource)` names the migrations not run yet through `MigrationExecutor.getPendingMigrations()` (read-only: it never creates the migrations table); `store.idempotency.purgeExpired(now?)` and `store.locks.purgeExpired(now?)` each delete expired rows and return a count; the app schedules both. Documented divergences from `createMemoryStore()`: opaque JSON loses `Date`/`undefined`/`Map` fidelity, `null` in an optional run or step property reads back absent, `save(key, undefined)` reads `{ result: null }`, `upsertDocument(..., undefined)` reads `doc: null`, `findDocuments` `where` is `jsonb` containment and orders by `document_id`, `find` ties break by uuid order.

Run references (`steps.insert`, `checkpoints.save`, `conversations.beginTurn`, and `runs.insert` of a child) map a foreign key violation (code `23503`) whose constraint is one of the runs table's foreign keys from the entity metadata (`runForeignKeyNames()`, the self foreign key included) to `RunNotFoundError` through `withRunReference()` (`repository/helpers.ts`), never the translated detail text. `runs.insert` of a run with `trigger.parent` goes through it because `orIgnore()` does not suppress a foreign key violation.

`chamvi_connections` holds `name` (varchar(64) `COLLATE "C"`, unique), `type`, `key_id`, `wrapped_key` bytea and timestamps; `chamvi_connection_entries` holds `connection_id` (FK `ON DELETE CASCADE`), `key` (varchar(255) `COLLATE "C"`) and `value` bytea. Entries are sealed bytes; the repository never sees plaintext or keys. `writeEntries` is one transaction: an `update()` of `updated_at` (existence plus a row lock serializing batches and `delete`), then the fence's lock row read `FOR SHARE` (`pessimistic_read`, owner), so an `acquire` taking the lease over, a `renew` or a `release` waits for the commit; then `expires_at > now` against a clock reading taken after both row locks are held (a reading before the waits would pass a lease that expired meanwhile, PR #165); no row or an expired one is `LeaseLostError` and a rollback. `replace` (the vault's recreate) is the same fenced transaction (connection row `FOR UPDATE`, then the fence, then delete and insert): an unfenced `delete` before the lease check would let an opener whose lease lapsed cascade away the next holder's entries (PR #165). A fence check outside the write's transaction (or a plain read without the row lock) would let a takeover slip between check and write. Memory checks the fence through the store's own `MemoryLockRepository.holds()` in the same tick, so a `MemoryConnectionRepository` needs the lock repository of its store. `locks.renew` is a transaction: the lease row `FOR UPDATE` (`pessimistic_write`, owner), then the clock, then `expires_at > now` and the update, for the same reason.

One baseline migration, `1794096000000-uuid-baseline.ts` (`UuidBaseline1794096000000`, generated from the entity metadata), creates the whole schema; the eight migrations before it are gone and every foreign key is validated. It cannot upgrade a database in place, so a deployment starts on a new, empty database. `assertStoreNotLegacy()` (`schema/legacy.ts`) refuses a database that records one of the earlier migrations or holds any `chamvi_*` table without the baseline recorded (a host app's own tables in the same database or schema do not count): `migrateStore` calls it before anything changes, and `chamvi start --check` calls it from `@chamvi/app`'s `modules/repository/module.ts` regardless of `CHAMVI_MIGRATE` (exit 1, error code `store_legacy_schema`). The message names the upgrade guide. This check is temporary: it goes, with its two call sites, in the chamvi version after the baseline (an old database then fails on `CREATE TABLE`).

## Module map (`packages/store-db/src`)

| Path | Purpose |
|------|---------|
| `entities/` | One TypeORM entity per table, the repositories the store queries through; `TableName` and the jsonb transformers (`JSON_VALUE_TRANSFORMER`, `OPTIONAL_JSON_TRANSFORMER`) in `constants.ts`, `toJsonParameter()` (jsonb sanitizing) in `asserts.ts` |
| `migrations/` | `1794096000000-uuid-baseline.ts` (`UuidBaseline1794096000000`, generated), the only migration |
| `conversation/` | `DatabaseConversationRepository` on the run DataSource, transaction-bound repository getters, shared core persistence policy and local options; identity-row locking, generation fences, journal and note-operation transactions, bounded operation-prune pages |
| `schema/` | `migrateStore()`, `pendingMigrations()` (`module.ts`), `assertStoreNotLegacy()` (`legacy.ts`, temporary), `STORE_ENTITIES`, `STORE_MIGRATIONS`, `MIGRATION_LOCK_NAME` |
| `repository/` | `createDatabaseStore()` (`module.ts`), entity to domain mapping, value builders and `RETURNING` row hydration (`helpers.ts`), `DatabaseStoreOptions`, `DatabaseStore` |
| `run/`, `step/`, `checkpoint/`, `idempotency/`, `lock/`, `effect/`, `state/`, `artifact/`, `agent-revision/`, `connection/` | Separate `Database*Repository` capability classes; idempotency and lock repositories each own numeric `purgeExpired()` |
