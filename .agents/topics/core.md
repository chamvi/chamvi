# Core Module Map

Read before adding or moving a file in `@chamvi/core` or `@chamvi/test-kit`.

## Module map (`packages/core/src`)

Every module is a folder with `module.ts`, `types.ts`, `asserts.ts`, `constants.ts` and an `index.ts` barrel as needed (see [conventions](../conventions.md#file-organization)).

| Path | Purpose |
|------|---------|
| `errors/` | one file per engine error (`ChamviError` and `ErrorCode` are `@chamvi/errors`) |
| `context/` | `defineContextKey()`, `inject()`, `tryInject()` (`module.ts`), `ContextKey`, `IContextProvider` (`types.ts`), the key `WeakSet` and the ToolContext `WeakMap`: `registerContextKey()`, `isContextKey()`, `bindProvided()`, `providedOf()`, `contextKeyName()` (`asserts.ts`, internal); `ContextNotProvidedError` lives in `errors/context-not-provided.ts` |
| `agent/` | `defineModelAgent()`, `AgentDefinition`, `AgentHooks`, `ToolCallInfo` (`types.ts`), budget defaults (`constants.ts`; the name rule is core-kit's), `assertToolsContext()`, `assertNoNeedsApproval()` (`asserts.ts`, internal) |
| `trigger/` | `assertTriggerKey()` (`key.ts`), `toInvoker()`, `idempotencyScope()` (`helpers.ts`, internal); `TriggerEnvelope`, `Invoker`, `TriggerParent` and `normalizeEnvelope()` live in `@chamvi/store` |
| `channel/` | `IChannel`, `ChannelRequest`, `ChannelContext`, `ChannelDispatchEnvelope`, `DispatchResult`, `ChannelMessage`, `ChannelSendOptions`, `ChannelSubscription`, `EmitMessage`, `ChannelHandle`, `ToolChannels`, `ConsoleChannelOptions` (`types.ts`); `consoleChannel()` (`console.ts`); `agentChannel()` (`agent.ts`); `AGENT_CHANNEL_NAME` (`constants.ts`); `assertChannelName()`, `createToolChannels()` (`ToolContext.channels`), `createChannelHandle()` (the emit effect and `approve()` with a channel) (`asserts.ts`, internal); `ChannelNotFoundError` lives in `errors/channel-not-found.ts` |
| `artifact/` | `ArtifactService` (`service.ts`), `ArtifactInput`, `ArtifactFilePart`, `IRunArtifacts` (`types.ts`); `ARTIFACT_URI_PREFIX` (`constants.ts`, internal); `artifactFilePart()` (public), `createRunArtifacts()`, `storeArtifact()` (`module.ts`, the last two internal); `assertArtifactInput()`, `toFilePart()`, `hydrateMessages()` (`asserts.ts`) |
| `run/` | `RunService` (`service.ts`: lineage, the update guards, the claim lease, `find` and `list(query)` with the wait kind split off to `findByWaitKind`), `Budget` (`maxSubtreeTokens`), `RunFindOptions`, `RunUpdateOptions` (`types.ts`), `waitIdOf()` (public), `readRun()` (`helpers.ts`); `Run`, `RunStatus`, `Step`, `Checkpoint`, `WaitPoint` live in `@chamvi/store` |
| `step/`, `checkpoint/`, `effect/`, `artifact/`, `state/`, `lock/`, `idempotency/`, `agent-revision/`, `connection/`, `conversation/` | One service each (`service.ts`; `conversation/service/` a folder; its context type in `types.ts`) over the port of `@chamvi/store`; see architecture.md → *Repository Contract* |
| `run/helpers.ts` | Also the internal shared abort-aware wait (`untilAborted()`) used by execution and memory-bound channel sends, not a public export. |
| `conversation/` | Optional conversation contract/types and limits, engine-local helpers, `ConversationService` (`service/`: the class in `module.ts`, its operations one file per concern: `scope.ts`, `turn.ts`, `items.ts`, `notes.ts`, `emit.ts`, `retention.ts`, `errors.ts`; `persistence/` its internal policy), execution bindings (`context.ts`) and capability (`module.ts`); trusted intake is bound by `Engine.channelContext()` (the `engine/conversations/` part), explicit `memoryTools()` and `hasConversation()` (`tools.ts`). |
| `engine/` | `Engine` (`module.ts`: the public facade; builds one `EngineContext` (`context/`: `createEngineContext()`, the services, settings, live lookups and shared mutable state every part reads by reference) and delegates to one class per part: `lifecycle/` (`EngineLifecycle`: start, stop, drain, poll), `intake/` (`EngineIntake`: dispatch and trusted channel intake), `cancel/` (`EngineCancel`), `conversations/` (`EngineConversations`), `guard/` (`EngineStartGuard`, the `prepareStart` predicate), `approvals/` (`EngineApprovals`: pause, resume, answer, `deliverApprovalMessage()` in `delivery.ts`), `runner/` (`EngineRunner`: claims and runs an execution), `registry/` (`EngineRegistry` in `engine.ts`; `withAgentLock()`, `agentCancelReason()`, `formatRevision()` (public) in `helpers.ts`; `cancelAgentRuns()`, `syncRevision()`, `claimRevision()`, `dropRevision()`, `releaseRevision()` in `module.ts`); each part's context is a `Pick` of `EngineContext` in its `types.ts`), `IEngine` (`types.ts`), `skills/` (internal `EngineSkills` implementing `IEngineSkills`: input capture, runtime validation, preparation and contribution lookup; no lifecycle coordination), `RunEvent`, `RunDelta`, `DispatchEnvelope`, `ApprovalAnswer`, `EngineStartOptions` (`types.ts`), `budget.ts` (stop conditions), `queue/` (`RunQueue`, `admitRun()` in `admission.ts`), `notify/` (`deliverOnce()`), `execute/` (`executeRun()` in `module.ts` drives one `RunExecution` (`run/`: `stream.ts`, `step.ts`, `pending.ts`, `settle.ts`); `SuspendRequest` = `ApprovalRequest \| DispatchWaitRequest` in `types.ts`; `helpers/` one file per concern, `pendingToolCalls()`, `withoutResults()`, `withToolResults()`, `executePendingCall()` in `pending-calls.ts` run the calls an approval suspended; `remote/` the remote stand-in), `remote/` (`caller/`, `receiver/`, `helpers/`: the peer side), `dispatch/` (`settledOutcomes()`, `answerDispatchWait()`, `expireDispatchWait()`, `healDispatchWaits()`, `cancelChildren()`, `healCancelCascade()`, `recomputeSubtreeUsage()`, `onRunSettled()` in `module.ts`; `DispatchEngineContext`, `ResumeRecord`, `ResumeStep` in `types.ts`; all internal), `AGENT_LOCK_TTL_MS`, `REVISION_PREFIX_LENGTH` (`constants.ts`, internal), `AgentChange`, `AgentRunsCancelled`, `EngineEvent` (`types.ts`) |
| `effect/` | `defineEffectTool()`, `effectMarker()` (`define.ts`), `wrapToolsForRun(tools, ctx, effects, { allow?, hooks?, trust? })` (`wrap.ts`: the tool-call frame, hooks, trust gate/result taint, effect lookup, `SuspendSignal` catch), `EFFECT`, `WrapToolsOptions`; `runToolCall()`, `currentToolCall()` (`frame.ts`, internal: the `AsyncLocalStorage` tool-call frame), `ToolCallFrame` (`types.ts`, internal) |
| `tool/` | `ToolContext`, `ToolTrust` (boolean or async predicates, plus the `approvalDetail` hook of the outbound gate's private body), `AgentTrust` (approve/deny policy and boolean tool-name overrides) (`types.ts`), `toolContextSchema` (`constants.ts`), `defineTool()` (`define.ts`), `hasToolContext()` (`asserts.ts`, internal) |
| `trust/` | Internal execution-bound first-taint persistence and final-input outbound approval/deny gate (`module.ts`), plus the public `runSource(ctx)` (`module.ts`: the source channel and address bound at execution start, `RunSource` in `types.ts`, the only exports of `index.ts`); agent policy/name validation and tool-level `assertToolTrust()` (`asserts.ts`). Shared by tool wrappers, resolved channel sends and approvals, and extraction. |
| `extract/` | `extract(ctx, { schema, content, instructions?, model? })`, `ExtractOptions`, tool-less structured output memoized in effects; conservative schema allowlist (`schema.ts`, internal: anchored patterns, property, free-text and output caps in `constants.ts`) taints results outside the allowlist; independent output check (`output.ts`) and raw-JSON cache validation on replay. |
| `dispatch/` | `dispatch()`, `dispatchTo()` (`start.ts`), `waitForDispatch()` (`wait.ts`), `agent` (`agent.on()`, `subscription.ts`), `AgentSubscriptionOptions`, `AgentSubscriber`, `DispatchInput`, `DispatchToInput`, `DispatchOutcome`, `DispatchWaitOptions` (public) and the internal `DispatchHost`, `DispatchRunSnapshot`, `DispatchWaitRecord` (`types.ts`), `DEFAULT_DISPATCH_ROLE`, `DEFAULT_DISPATCH_MAX_DEPTH`, `DEFAULT_MAX_DISPATCHES_PER_RUN`, `DEFAULT_DISPATCH_WAIT_TIMEOUT_MS` (public) and `DISPATCH_CONTEXT` (internal, key `dispatch`) (`constants.ts`), `helpers/` (internal, one file per concern: `roles.ts` (`findDispatchRole()`, `assertDispatchRoles()`), `lineage.ts` (`ancestorsOf()`), `snapshot.ts` (`bindRunSnapshot()`/`runSnapshotOf()`), `wait-record.ts` (`readDispatchCount()`, `readDispatchChildren()`, `toWaitRecord()`), `keys.ts` (`dispatchClaimKey()`), `outcome.ts`, `payload.ts`, `serial.ts`, `source.ts`, `subscription.ts`), `peer/` (the peer dispatch path), `findApprovalWaitBelow()` (`descendants.ts`, public: the batched approval walk http and cron share) |
| `approval/` | `approve()`, `outboundApproved()` (public: the outbound gate approved the current call) and the internal `requestApproval()`, `reserveApproval()`, `SuspendSignal` (`request.ts`), `ApprovalRequestInput`, `ApprovalDecision`, `ApprovalOption` (`types.ts`), `DEFAULT_APPROVAL_TIMEOUT_MS`, `APPROVAL_TIMEOUT_MAX_MS`, `APPROVAL_OPTION_ID_PATTERN`, `APPROVAL_OPTION_LABEL_MAX_LENGTH`, `APPROVAL_OPTION_DETAIL_MAX_LENGTH`, `APPROVAL_OPTIONS_DETAIL_MAX_LENGTH` (public), `SUSPENDED_RESULT` (internal) (`constants.ts`), `approvalDecisionKey()`, `toApprovalDecision()`, `toApprovalOptions()`, `assertSelectionShape()`, `toSelection()` (`helpers.ts`, internal) |
| `limit/` | `LimitService` (`service.ts`: `used`, `record` insert-if-absent, `purgeExpired` over `ILimitRepository`), `ToolLimit`, `AgentLimits`, `ILimitService` (`types.ts`), `bindToolLimits()` and the check, bound approval and counting `enforceToolLimit()` (`module.ts`, internal), scope/key/weight rules (`asserts.ts`, `helpers.ts`, internal) |
| `permission/` | `requireToolPermission()` (`policy.ts`, `can` of `@chamvi/access`), `RequireToolPermissionOptions` (`types.ts`); the check, the names and the binding types live in `@chamvi/access` |
| `actor/` | `ActorContext<TIdentity = Invoker>` (`types.ts`, authup's shape without `INarrowablePermissionEvaluator`), `isActorGranted()`, `isActorGrantedSome()` (false only on a `PermissionError`), `forbidden()` (`helpers.ts`), `SystemPermissionEvaluator` (`evaluator.ts`), `createSystemActor()`, `isSystemActor()` (`system.ts`). The system actor is recognized by identity of the object only (a module-private `WeakSet`, never its `identity`); no request path builds it; eslint refuses its import outside core, app, test-kit |
| `service/` | `AbstractEntityService` (`module.ts`): `isGranted`, `isGrantedSome`, `assertGranted` over `actor/helpers.ts` (`forbidden(name)` on a failed check) |
| `message/` | Native SDK message/content aliases (`types.ts`), exported through the core barrel; internal instruction validation, normalization, leading-system split and transcript trust guards (`helpers.ts`). |
| `skill/` | Generic `SkillInput`, `ISkillRuntimeProvider`, `ISkillRuntime`, `ISkillPreparation`, `PreparedAgentSkills` and `SkillContribution` (`types.ts`); protocol compatibility and opaque input snapshots (`helpers.ts`). Engine coordinates preparation, cancellation, readiness and ordinary contributed tools. No skill domain types, catalogs, hashes, content, source caches, filesystem or SDK dependencies. |
| `state/` | `createAgentState()` (`module.ts`, validation via `@validup/standard-schema`), generated tools (`tools.ts`) |
| `model/` | `ModelRef`, `IModelResolver`, `ModelCheckOptions` (`types.ts`, public region) and the internal `ModelContext`; `checkAgentModel()`, `resolveModel()` (public) and `checkDefaultModel()` (`module.ts`); `toLanguageModel()` (`asserts.ts`, internal: the one resolution path of the engine and `resolveModel`); `MODEL_CONTEXT` (`constants.ts`, internal, key `model`) |
| `clock/` | `IClock`, `systemClock` |
| `keyring/`, `connection/` | Keyring and sealing, the connection vault, validation and handle types; see [connections.md](connections.md) |

`src/index.ts` re-exports each folder's `index.ts`. `@chamvi/test-kit` (`packages/test-kit/src`) holds `model/` (`mockModel`, `textModel`, `approvalModel`, `failingModel`, `MockPart`, `MockResponse`), `model/embedding.ts` (`mockEmbeddingModel`, `MockEmbeddingModel`), `skill-runtime/` (`fakeSkillRuntime`), `clock/` (`ControllableClock`), `knowledge-contract/` (`describeKnowledgeRepositoryContract`, structural `Contract*` types, `KnowledgeRepositoryContractFactory`), `fixture/` (`testUuid`, the record makers), `entity-contract/` and a `<aggregate>-contract/` per port (`describe<Port>RepositoryContract`), `engine/` (`createTestEngine`), `database/` (`createTestDataSource`, store-db by variable specifier), `workspace-contract/` (`describeWorkspaceContract`, `WorkspaceContractFactory`), `git-fixture/` (`createGitFixture`, `GitFixture`) and `github-fake/` (`createFakeGithub` in `module.ts`, `FakeGithub`, `FakeGithubOptions`, `FakeRequest`, `FakeRoute*`, `JwtClaims` in `types.ts`, the repository routes and `abortable()` in `asserts.ts`).
