# Calendar Tools

Read before changing `@chamvi/tool-calendar`.

`@chamvi/tool-calendar` holds `calendarTools({ accounts?, client?, timezone?, timeoutMs?, fetch?, clock? })`, two plain `defineTool()` tools (`calendar_list`, `calendar_events`) over one `ICalendarClient` (`createCalendarClient(accounts, options)`), and on `/module` `toolCalendarModule()`. It peers on core and `ai` (optional peer on app) and depends on `tsdav`, `ical.js` and `smob`, pinned to exact versions; times use Node 26's `Temporal`. Options are checked when called (`InvalidAgentDefinitionError`, never echoing a password); `accounts` and `client` together are refused.

## Invariants

- **Read-only on the wire.** Every request goes through `guardedFetch()` (`client/guard.ts`) around the given or global `fetch`: only `CALENDAR_ALLOWED_METHODS` (`PROPFIND`, `REPORT`, `GET`) pass, any other method (also a `Request`'s own) throws a `calendar_request` error before anything is sent. tsdav gets this fetch for its login and every call; never hand it the raw fetch. Proven by `test/unit/client/methods.spec.ts` (the recorded methods of a full list and events call, the guard on its own).
- **Calendar ids**: `<account>:<last path segment of the calendar URL>`. Only calendars whose components include `VEVENT` are listed (reminder lists skipped), once per session. An unknown account prefix or calendar is a `ValidationError`.
- **Expansion here, not on the server** (`expand/module.ts`): `fetchCalendarObjects` with the time range and `useMultiGet: false`, then `expandEvents()` per resource with ical.js. Recurring events iterate from DTSTART with EXDATE and RECURRENCE-ID exceptions (a moved occurrence replaces its slot; a CANCELLED one is kept with `status`), stopping at `to` or after `CALENDAR_EXPAND_MAX_ITERATIONS` (10 000) iterations per event. An exception without its master is a single event. A resource that is no iCalendar is skipped. An event is in range when it ends after `from` and starts before `to`.
- **Zones**: every time is read and printed in the configured zone (`timezone`, default `CALENDAR_DEFAULT_TIMEZONE` `Europe/Berlin`; an IANA id or `UTC`), never the process zone. `instantOf()`: a date is midnight in the zone; a TZID ical.js resolved from a VTIMEZONE, or a floating time whose TZID is an IANA id, is read in that zone; a non-IANA VTIMEZONE keeps its own rules; any other floating time is read in the configured zone. Timed events give ISO with the zone's offset, all-day events plain dates, `end` exclusive (a derived end, from DURATION or none, uses the start's zone). The expand spec runs with `TZ=America/New_York`.
- **Caps**: `from`/`to` at most `CALENDAR_RANGE_MAX_DAYS` (92) apart, `to` after `from` (a date is midnight in the zone); `limit` default `CALENDAR_EVENTS_DEFAULT_LIMIT` (100), at most `CALENDAR_EVENTS_MAX_LIMIT` (500), `truncated` when more matched; `description` cut at `CALENDAR_DESCRIPTION_MAX_CHARS` (2 000), `title`, `location` and `organizer` at `CALENDAR_FIELD_MAX_CHARS` (500; every occurrence of a recurring invite repeats them), never inside a surrogate pair. Events across accounts are sorted by start (all-day first, then uid). `attendees` is `{ count, self? }`, `self` the PARTSTAT of the attendee whose address is the account user.
- **Sessions and errors** (`client/module.ts`): one tsdav session per account, logged in on first use (Basic auth); a failed login, or one cut by the timeout or a cancel, is not reused. `request()` races each account's call against `timeoutMs` (default `CALENDAR_TIMEOUT_MS` 30 s) on the `IClock` and the run's signal. A failure that is not a `ChamviError` becomes code `calendar_request` (`CALENDAR_REQUEST_ERROR_CODE`) with the message `<tool>: <account>: request failed` (or `timed out`): tsdav's messages can carry URLs and server text, so they are dropped. `close()` forgets the sessions.
- **Trust**: both tools are `trust: { taint: true }` (calendar names and invites come from other people) and end their description with `UNTRUSTED_NOTE`.
- **Env contract** (`module/helpers.ts`, read when `toolCalendarModule()` is called): `CHAMVI_CALENDAR_ACCOUNTS` (`CALENDAR_ACCOUNTS_VARIABLE`) is a JSON array of `{ id?, url, address? }`; `id` defaults to the address with `@` and `.` as `-` and is required without one; `url` http(s); credentials `CHAMVI_CALENDAR_<ID>_USER` (default the address) and `CHAMVI_CALENDAR_<ID>_PASSWORD` (each in env or the store: checked in `setup`, missing from both fails naming the variable, never at the factory), `<ID>` upper-cased with `-` as `_` (colliding ids refused), each also as `<name>_FILE` (one trailing newline trimmed; both set is an error). `CHAMVI_CALENDAR_TIMEZONE` wins over the `timezone` option. Errors name the variable and index, never a value. In `setup` (`module/type.ts`) stored rows of type `calendar` named `calendar-<id>` are added and merged per field through `resolveConnection`, with the rules of [mail-tools.md](mail-tools.md); `uniqueId` is URL and user (one CalDAV URL serves many users). No accounts: the context stays provided and each tool fails with `connection_not_configured` (`calendarTools()` outside the module still fails with `context_not_provided`). Migrate mode does nothing; the client closes on `drained` and in `teardown`.
- **Privacy**: the package has no access control of its own. Events land in the run's steps and checkpoints and shape the model's answer, so whoever reads the agent's runs reads the calendar; such agents should be `private: true` (only `agent:<name>:read` reads them), as the README and examples show. Credentials never reach a tool input, a result, an error or a log.

## Testing

- No test reaches a real server. `createFakeCalDav()` (`test/utils/caldav.ts`) is a CalDAV server behind a `fetch` in the iCloud shape (`.well-known` redirect to a partition host, principal, an absolute calendar home with `:443`, `supported-report-set`, `calendar-query` REPORTs), recording every request (`requests`: method, url, depth, authorization); `hang` and `status` drive the timeout (on a `ControllableClock`) and the 401 tests. `calendar()`, `vevent()`, `BERLIN_VTIMEZONE` and `weeklyStandup()` (`test/utils/ics.ts`) build iCalendar text; `toolContext()`/`callTool()` (`test/utils/tools.ts`) call the tools as the AI SDK does.
