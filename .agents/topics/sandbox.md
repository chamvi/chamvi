# Sandbox

Read before changing `@chamvi/sandbox` or a provider (`sandbox-local`, `sandbox-docker`, `sandbox-k8s`). Git credentials and tools: [sandbox-git.md](sandbox-git.md); coding tools and repository instructions: [coding.md](coding.md).

`@chamvi/sandbox` holds the contracts and shared rules, three providers implement them, `@chamvi/coding` adds the coding tools. Nothing in these packages throws `FatalToolError`: model input the model can correct is a core `ValidationError`, a workspace or provider failure a core `SandboxError` (`sandbox_error`), both tool errors; option misconfiguration is `InvalidAgentDefinitionError`.

- **Contracts**: `ISandboxProvider { name, create(options), find(runId, { deployment?, signal?, rebuild?: { env?, limits? } }), collectGarbage({ deployment?, isSettled?, isSuspendable? }) }`; `IWorkspace { id, info, disposed, exec(argv, { cwd?, timeoutMs?, stdin?, signal? }), readFile(path), readBytes(path), writeFile(path, content: string | Uint8Array), dispose() }`; `IExecTransport { exec(argv, { stdin?, stdout, stderr, signal }) -> { exitCode }, alive?(signal), remove() }` (`stdout`/`stderr` are `IOutputSink`s the workspace owns). `WorkspaceCreateOptions { runId, repo?, ref?, checkout?: { depth?, credential? }, image?, env?, limits?, deployment?, signal? }` (`repo` already normalized; `deployment` default `DEFAULT_DEPLOYMENT` `'default'`, a label value, `assertDeployment`). No `git` method: git is `exec(['git', ...])`. Workspace ids are `randomUUID()`, so `chamvi-ws-<id>` is a valid container name, pod name and label value. A provider builds `WorkspaceInfo { runId, provider, repo?, ref?, commit?, defaultBranch?, image?, createdAt, expiresAt }`, calls `prepareWorkspace(workspace, { ...checkout, repo, ref, signal })` and assigns its `{ commit?, defaultBranch? }` to the info; `IWorkspace.redact?(text)` exists on the manager's credential view only; a failed checkout disposes the workspace. `find` answers every live, unexpired workspace of the run in the deployment (the instance the process holds, else one rebuilt from what lives with the workspace); it never creates a workspace but may restart one (Docker) or rebuild its pod (k8s persistence, with `rebuild`: the manager's `env`/`limits`, never stored with the workspace, which may hold secrets).
- **Rules** (every provider): exec takes argv only (`readonly string[]`, non-empty, no NUL); the only shells are the coding tools' `sh -c` scripts inside the workspace (the command a positional argument, never interpolated). Paths (`resolveWorkspacePath`) are relative to the root or under `/workspace/`, the model always sees `/workspace`; empty, NUL, other absolute paths and escapes are `ValidationError` before any filesystem or exec call. Output is capped per stream at `OUTPUT_MAX_BYTES` 65 536 (`createOutputCollector`: drains past the cap, holds at most the cap, a cut UTF-8 character dropped) with `stdoutTruncated`/`stderrTruncated`. Files have at most `FILE_MAX_BYTES` 16 MiB; `readBytes` returns the raw bytes, `readFile` decodes them strictly (`decodeUtf8File`, a file that is not valid UTF-8 is a `SandboxError`), `writeFile` takes UTF-8 text or bytes. Exec timeout default `EXEC_TIMEOUT_MS` 300 s, max `EXEC_TIMEOUT_MAX_MS` 1800 s, never past `expiresAt`; `timedOut` is a result. A command that cannot start exits 127.
- **Repositories** (`normalizeRepo`): `owner/name` -> `https://github.com/owner/name.git`, an https URL without credentials, query, fragment or a malformed percent escape (`decodeRepoPath`, which the credential lookups share), `file:///abs` only with `allowFileRepos`; `allowRepo(url)` narrows; the `ValidationError` never echoes the input. Refs (`assertGitRef`): `^[A-Za-z0-9][A-Za-z0-9._/+-]{0,254}$` without `..`, `//`, `@{`, `/.`, a trailing `/` or `.`, `.lock`. Checkout (`prepareWorkspace`, same on every provider, through the workspace's own exec): `git init -q .`, `git remote add origin <url>`, `ls-remote --symref <url> HEAD` (the default branch, `parseDefaultBranch`, dropped unless `isGitRef`), `fetch -q [--depth <n>] origin <ref or the default branch> [<default branch>]` (full history unless `checkout.depth`), `git checkout -q -B <ref> --track origin/<ref>` when `refs/remotes/origin/<ref>` exists, else `git -c advice.detachedHead=false checkout -q FETCH_HEAD`, `git rev-parse HEAD`, then `git config chamvi.defaultBranch <name>` (`CHECKOUT_DEFAULT_BRANCH_KEY`) and, last, `git config chamvi.checkout <sha>` (`CHECKOUT_KEY`); with an https `checkout.credential`, the workspace read credential helper is installed before the remote calls (for the workspace's later git calls), and `ls-remote` and the fetch run through `gitArgv()`'s `GIT_AUTH_SCRIPT` with the credential on stdin, so its config checks (`http.proxy`, `http.sslVerify` false, CA paths, `curloptResolve`, remote proxies, URL rewrites of an image's `~/.gitconfig` or the repository config) refuse the checkout instead of carrying the read token; anonymous and file calls reset the helper and disable hooks; repo-less workspaces only `git init`, then `chamvi.checkout none` (`NO_REPO_CHECKOUT`). `readCheckout()` reads both back through one `git config --get-regexp` when a provider finds the workspace (`{ commit, defaultBranch? }`, `{}` repo-less, `undefined` when the checkout record is missing (git exits 1) or not fitting `info.repo`; any other failed read, e.g. right after a container restart, is retried on the provider's `IClock`, `CHECKOUT_READ_ATTEMPTS` 5 reads `CHECKOUT_READ_RETRY_MS` 500 ms apart): every provider's `find` skips a workspace without it, a create that died before its checkout finished (a process killed during the fetch), leaving it to the collection, and the manager never adopts a found workspace of a repository without `info.commit`. A failed step is a `SandboxError` with the first 2000 characters of git's stderr.
- **Environment and limits**: containers and pods get only `SANDBOX_ENV` (`HOME` = `WORKSPACE_HOME` `/home/sandbox`, a disk-backed volume of the workspace (Docker: anonymous volume, k8s: emptyDir), kept across a restart, never the memory-backed `/tmp`, so cargo, rustup, Maven, Gradle and mise's global config and shims stay out of the memory limit, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `safe.directory=/workspace` via `GIT_CONFIG_COUNT/KEY_0/VALUE_0`, `NPM_CONFIG_UPDATE_NOTIFIER=false`, `CI=true`) plus `CACHE_ENV` (`XDG_CACHE_HOME`, `npm_config_cache`, `PIP_CACHE_DIR`, `GOMODCACHE`, `GOCACHE`, `COMPOSER_CACHE_DIR`, each a folder under `CACHE_DIR` `/cache`; package download caches only, never a home holding credentials or installed programs, so no `CARGO_HOME` and no `MISE_DATA_DIR`: mise keeps its toolchains in its default `$HOME/.local/share/mise`, per workspace) plus the configured `env` (`assertSandboxEnv`: keys `^[A-Za-z_][A-Za-z0-9_]*$`, no NUL); local gets the host `PATH`, `HOME`/`TMPDIR` in its folder, the same git settings minus `safe.directory` and, unless `cache: false`, `cacheEnv(<root>/.cache)` (created lazily by the tools; no workspace id, so never collected). `DEFAULT_LIMITS` `cpu '1'`, `memory '2Gi'`, `storage '4Gi'`, `pids 512`, `maxLifetimeMs 604_800_000` (7 days; `resolveLimits` merges layers over them and refuses the former `timeoutMs`, Kubernetes quantities); `/tmp` is a tmpfs of the providers' `tmpSize` (`TMP_SIZE` 1 GiB, `assertTmpSizeOption`). **Usable inside, strict at the edge**: Docker and k8s run root (`0:0`) with a writable root filesystem by default, every capability dropped but `ROOT_CAPABILITIES` (`CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `FSETID`, `SETUID`, `SETGID`, `KILL`, added only for a root user, `isRootUser()`), keeping `no-new-privileges`/`allowPrivilegeEscalation: false`, seccomp `RuntimeDefault` (k8s), the limits and no host mount but the cache; `user` and `readOnlyRoot` restore the hardened mode (no capability; k8s adds `runAsNonRoot` and `fsGroup`), the only one Pod Security `restricted` admits (the default needs `baseline`). **Cache**: every container and pod mounts `/cache` (Docker: an anonymous volume per workspace by default, or the named volume of `cache: { volume }` (`false` and `{}` refused, `InvalidAgentDefinitionError`), a trust boundary shared by every run and agent on the host; never a non-root `user` on a volume a root workspace wrote, since it leaves root-owned folders below the top level; k8s: the RWX claim of `cache: { claimName }`, else an emptyDir), so `CACHE_ENV` always points at a writable folder (Docker with a non-root `user`: after the probe `openCache()` runs `CACHE_OPEN_SCRIPT` as `0:0` through a second remote workspace, `chmod 1777` on `/cache` and the `CACHE_ENV` folders root owns (made when missing: Docker makes an absent mount point root 0755; deeper folders a root workspace made stay root's); a failure is a `SandboxError` and the create disposes; k8s relies on `fsGroup`, which a claim on an NFS-style plugin ignores); a shared cache (opt-in) is shared trust (documented risk: a package one run fetched); chamvi's own commands never resolve into it: `PATH_GUARD_SCRIPT` (internal, `image/constants.ts`) drops every `PATH` entry at or under `/cache` at the start of `EXEC_SCRIPT` (so the `timeout` wrapper, the checkout's `git` and every command) and of the probe; the runtime still resolves the outer `sh` on the container's PATH, so an image or `env` must not put a `/cache` folder on it. **Allow-listed images**: `create_workspace({ image })` (`assertImage`, `IMAGE_PATTERN` internal) has the `image` parameter only when the manager has `allowImage` and the provider is not `local` (`offersImage()`, `manager/helpers.ts`); a requested image otherwise is a `ValidationError` before any create; `sandboxModule()` reads `CHAMVI_SANDBOX_IMAGES` (comma list, exact references, `readImageAllowList()` in `module/helpers.ts`; an entry that is none names the variable), which wins over `allowImage`. The operator's pull policy (Docker `pull`, k8s `imagePullPolicy`) applies to every image. `probeImage(transport, { image, clock?, signal? })` runs `IMAGE_PROBE_SCRIPT` straight on the transport after start and before the checkout (every workspace exec goes through `timeout`): a `SandboxError` names what is missing of `IMAGE_REQUIREMENTS` (`sh`, `git`, a `timeout` with `-k`, `/bin/sh`, and `head`, `base64`, `tr` on `/usr/bin:/bin`, the only PATH the repository guidance collector uses), `IMAGE_PROBE_TIMEOUT_MS` 30 s on the clock; the create then disposes the container or pod. **Lifetime follows the run, up to the cap**: containers and pods replace the image's entrypoint; containers and pods run `SLEEP_UNTIL_SCRIPT` (public, `@chamvi/sandbox` `provider/constants.ts`: `sh -c` sleeping until `ceil(expiresAt / 1000)` epoch seconds, so a container `find` starts again after a restart and a pod scheduled or started late stop at the same time, and exit at once past it), a pod with `lifetimeSeconds(info)` (public, `provider/module.ts`: `ceil((expiresAt - createdAt) / 1000)`, at least 1; `restartPolicy: Never`, so it never starts over) as its `activeDeadlineSeconds` beside it, so a workspace stops itself at `expiresAt` even when no collection runs and nothing kills it earlier; `maxLifetimeMs` is the hard cap from the creation (never renewed) and `expiresAt`, exec timeouts stay bounded by it; a Docker container `find` restarts sleeps the full lifetime again, but `find` never restarts an expired one. Labels (`workspaceLabels()`): `SANDBOX_LABELS` (`app.kubernetes.io/managed-by=chamvi`, `app.kubernetes.io/component=sandbox`), `chamvi.dev/run`, `chamvi.dev/workspace`, `chamvi.dev/deployment` (`DEPLOYMENT_LABEL`), with a repository `chamvi.dev/repo-key` (`REPO_KEY_LABEL`, `repoKey()`: 32 hex of the URL's sha256, as label values are limited). Metadata (`workspaceMetadata()`, Docker labels, k8s annotations, read back by `readWorkspaceInfo()`): `chamvi.dev/created-at`, `chamvi.dev/expires-at` (epoch ms), `chamvi.dev/repo`, `chamvi.dev/ref`, `chamvi.dev/image`. No agent label (names may exceed 63 characters).
- **Remote workspaces** (`createRemoteWorkspace`, Docker and k8s): argv wrapped as `timeout -k 5 <s> ...` (`wrapTimeout`; GNU `timeout` signals its process group, BusyBox `timeout` only the command it execs) inside `EXEC_SCRIPT` (`sh -c` with a fresh marker `chamvi-exit-<32 hex>:` and the cwd made absolute under `/workspace`): the script enters the cwd (else prints `<marker>cwd` and the exec rejects `SandboxError('cwd /workspace/<p> is no directory in the workspace.')`, as on local), runs the command and prints `<marker><status>` on stderr. The workspace owns the output collectors and cuts the marker out of stderr (`createExitMarkerFilter`, also split across chunks); `EXIT_DRAIN_MS` 2 s after the marker it settles with that exit code and the output so far and detaches the transport, so a background job holding the output (`node server.js & echo started`) never stalls an exec, on Docker (whose daemon drains 2 s too) and k8s (whose exec status waits for every pipe writer). A client-side guard at timeout + `EXEC_GRACE_MS` 15 s (exit 137, `timedOut`, the output so far); `timedOut` also for exit 124/137/143 once the timeout passed (`isTimeoutExit`; 143 is BusyBox's TERM of the command). `readBytes` (and `readFile` over it) is `cat -- <abs>` capped at `FILE_MAX_BYTES + 1`, `writeFile` `sh -c WRITE_FILE_SCRIPT` with the bytes on stdin (`head -c <bytes>` into `.chamvi-write-<16 hex>` next to the file, mode kept by `cp -p`, then `mv -f` over it, so a concurrent reader never sees a cut file; a symbolic link or a directory that takes no new file is written in place; no stdin EOF needed, so k8s `v4` works). A transport result with `closed` (the Docker daemon reset the connection, e.g. a command that exited with stdin still queued) is accepted only after the exit marker, else the exec rejects, since the output may be cut. Abort detaches (the transport drops the stream); dispose rejects every in-flight exec with `SandboxError('workspace disposed')`, then `transport.remove()` (retried on a later dispose after a failure). A failed exec asks the optional `transport.alive(signal)` (bounded by `ALIVE_PROBE_TIMEOUT_MS` 5 s; a rejection or no answer reads as alive): `false` (Docker: inspect 404 or `State.Running` false; k8s: read 404, a `deletionTimestamp`, or `podState` failed) marks the workspace gone, so `IWorkspace.disposed` reads true and every call rejects with "workspace <id> is gone ...; call create_workspace for a new one" (local: its directory missing, checked when a cwd or file is missing and before every write).
- **Providers**: `createLocalSandbox({ root?, env?, limits: { maxLifetimeMs }?, clock? })` (`<root>/<id>/{workspace.json,home,tmp,repo}`, the record `find` rebuilds the workspace from (without `deployment` it reads as `default`; folder `0700`, record `0600`: it holds the create's `env`), `writeFile` through a temporary `.chamvi-write-<hex>` file with the old mode and a `rename`, like the remote script; file paths and the cwd resolved with `realpath` before each call and refused (`ValidationError`) when they leave the root through a symbolic link or pass a dangling one (remote providers need no check: a link resolves inside the container), spawn with `detached: true`, timeout/abort/dispose kill the group with `SIGKILL`, the kill timer cleared on exit, `KILL_GRACE_MS` before closing pipes a leaver holds; a command that exited while a background job holds its pipes settles `KILL_GRACE_MS` after its `exit` with its own code, and its group is remembered while a member runs (dropped once `process.kill(-pgid, 0)` fails, checked every `LINGER_CHECK_MS` 1 s, so a reused group id is not killed), killed on dispose and when the directory is gone; only the spawning instance knows the groups, so a `process.on('exit')` listener (`killLingeringJobs()`) kills them at exit and a workspace `find` rebuilds has none; no isolation). `createDockerSandbox({ docker?, image?, network?, pull?, env?, limits?, user?, readOnlyRoot?, cache?, tmpSize?, clock? })`: container `chamvi-ws-<id>`, `Entrypoint: []`, `Cmd` `SLEEP_UNTIL_SCRIPT`, `User` = `user` (default `DEFAULT_USER` `0:0`, also the exec user of the transport), `ReadonlyRootfs` = `readOnlyRoot`, `CapDrop ALL` plus `CapAdd ROOT_CAPABILITIES` for root, `no-new-privileges`, `Init: true` (docker-init as pid 1 reaps the orphans of any image, also one without an init), `PidsLimit`, `Memory` = `MemorySwap`, `NanoCpus`, `/tmp` tmpfs `rw,exec,nosuid,nodev` (Docker adds `noexec` unless `exec` is given), anonymous `/workspace` and `/home/sandbox` volumes removed with `{ force: true, v: true }` and the `/cache` volume; `pull` `'missing'` (pull once on a 404), `'always'`, `'never'`, for every image; the create's `signal` reaches the pull, the container create (one made anyway removed by name) and the start; `network` default `bridge`, `none` allowed (repo-less only); storage not enforced; `find` lists the run's containers by label (`all: true`), starts an `exited` one again (a host or daemon restart, a suspension; the volume holds the work) and skips a never-started one (a crashed create); a held handle whose container stopped reads as gone (`alive`), and the next `find` drops it and restarts the container under a fresh handle (never one whose `dispose` was called, tracked in a `WeakSet`, also after a failed removal). `createKubernetesSandbox({ namespace, kubeConfig?, image?, env?, limits?, podLabels?, imagePullPolicy?, user?, readOnlyRoot?, cache?, persistence?, tmpSize?, startTimeoutMs?, pollMs?, clock?, client? })`: a bare pod (`restartPolicy: Never`, `SLEEP_UNTIL_SCRIPT`, `activeDeadlineSeconds` `lifetimeSeconds(info)`, `automountServiceAccountToken: false`, `enableServiceLinks: false`, `shareProcessNamespace: true` (the pause container is pid 1 and reaps orphans of any image), `runAsUser`/`runAsGroup` from `user` (`PodUser { uid, gid }`, default 0), seccomp `RuntimeDefault`, `readOnlyRootFilesystem` from `readOnlyRoot`, caps dropped (root: `ROOT_CAPABILITIES` added), requests = limits incl. `ephemeral-storage`, emptyDir `/workspace` with `sizeLimit`, memory emptyDir `/tmp` of `tmpSize`, disk emptyDir `/home/sandbox`, `/cache` claim or emptyDir), `podLabels` may not name a managed label (deployment and repo key included); `find` lists the run's pods by label selector (none for a run id that is no label value) and returns only running ones without a `deletionTimestamp` (a failed or finished pod is gone); `create` polls the pod on the `IClock` every `POLL_MS` up to `START_TIMEOUT_MS` (120 s) and fails fast on `FATAL_WAITING_REASONS`; `IPodClient` wraps `CoreV1Api` and `Exec` (stdin closed only on `v5.channel.k8s.io`; the claim methods optional, required with `persistence`, else `InvalidAgentDefinitionError`); pids via the kubelet's `podPidsLimit`. **Persistence** (`{ storageClassName?, size? }`, opt-in): `create` makes a RWO claim `chamvi-ws-<id>` (`buildClaim()`: the pod's labels and annotations, `size` default `limits.storage`) before the pod, which mounts it at `/workspace` and `/home/sandbox` (subPaths `workspace`, `home`) instead of the emptyDirs; a failed create and `dispose` delete both; `find` rebuilds the pod of a live claim (unexpired, not deleting) without a running one: image and expiry from the annotations, env and limits from the provider plus `rebuild`, `activeDeadlineSeconds` the remaining lifetime (at least 1), the `create` wait and probe, a pod create `409` waits for the other's pod; a failed rebuild throws `SandboxError`, never skips the claim (`acquire` would make an empty workspace). A node-local class (local-path) pins the rebuilt pod to its node. RBAC: `pods` create/get/list/delete, `pods/exec` get and create, with persistence `persistentvolumeclaims` create/get/list/delete. All three run `describeWorkspaceContract`.
- **Garbage collection** (the reaper; a workspace also stops itself at `expiresAt`): `provider.collectGarbage({ deployment?, isSettled? })` deletes that provider's workspaces of the deployment that expired (local: folders whose `workspace.json` expired; Docker: containers with the managed labels past `expires-at`; k8s: pods past the annotation or in phase `Failed`/`Succeeded`) and, with `isSettled`, those whose run settled or does not exist (`createSettledCheck()`: asked once per run and pass, a rejection keeps the workspace and counts as a failure), disposing open ones of the process first; k8s with persistence also deletes claims that expired or whose run settled, pod or not (a claim without a pod may be suspended: no orphan rule). With `isSuspendable` (`createSuspendableCheck()`, same rules) a provider **suspends** the running workspaces of a kept run, never removing them (not counted; removal wins), and drops its held handle without a dispose: Docker stops the container (files, root fs and volumes kept), k8s with persistence deletes the pod and keeps the claim, others ignore it. Suspension loses background jobs and `/tmp`, on k8s also root fs writes and an emptyDir `/cache`. A removal that fails never stops the pass: the rest go on, and one `SandboxError` (`collectionError()`, the count and the first message, every failure in an `AggregateError` cause) is thrown at the end. Workspaces without a deployment label are never seen.
- **Manager** (`createWorkspaceManager({ provider, image?, env?, limits?, allowFileRepos?, allowRepo?, allowImage?, maxWorkspacesPerRun?, gcIntervalMs?, deployment?, isSettled?, isSuspendable?, credentials?, depth?, author?, push?, clock?, onError? })`): workspaces keyed by `(runId, normalized repo or '')`; on a miss (`get` without a held workspace that fits, `acquire` of a key it does not hold, `release` of an id it does not hold) it asks `provider.find(runId, { deployment })` (concurrent misses of a run share one lookup, a failure is `SandboxError('workspace lookup failed: ...')` and not cached) and adopts what it finds by `info.repo` (a second workspace of one key stays unused, a key being created is never replaced), so a run reaches its workspaces after an approval pause, a restart or on another replica; a release of the whole run while a lookup runs disposes what that lookup found; `acquire(runId, { repo?, ref?, signal? })` shares one create per key (`reused`), refuses another ref of a held repo and more than `maxWorkspacesPerRun` (default `MAX_WORKSPACES_PER_RUN` 3; pending creates count) with a `SandboxError` that names the option; `get(runId, id?)` (async; the run's only live workspace without an id, `ValidationError` for several) disposes expired ones and answers "not found" for an id of another run; a gone (`workspace.disposed`, not expired) one is forgotten **without a dispose** (which would remove a stopped container with its volume) and treated as a miss, so the lookup finds it again restarted (Docker) or, when `find` reports nothing, `get` throws its gone message once; `acquire` disposes an expired workspace, forgets a gone one the same way and creates anew only when the lookup finds nothing; `release(runId, id?)` (the whole run: the held workspaces, then every one `find` reports for the run); `attach(engine)` releases a run on `run.updated` with `completed | failed | cancelled` (kept while `waiting` or `interrupted`), so also the workspaces another process created; with `isSettled`, a run this process neither holds nor looks up gets no `find` (one container or pod list per settled run, and on Docker a restart of a stopped container) but starts a rate-limited collection, which removes what other processes left for it; `collectGarbage()` disposes its own expired workspaces and, with `isSettled`, releases the held runs that settled, with `isSuspendable` forgets (never disposes) the held workspaces of suspendable runs, so their next `get`/`acquire` finds them again (`find` with `rebuild`), then calls the provider's with `{ deployment, isSettled, isSuspendable }` (false for a run it still holds anything of: it cannot mark those handles gone) (started by `acquire` and by such a settled run at most every `GC_INTERVAL_MS` 10 min, `0` disables); `close({ timeoutMs?, dispose? })` unsubscribes, aborts the creates in flight (each create gets the caller's signal combined with a per-entry abort; what they make anyway is disposed) and forgets the held workspaces **without disposing them** (they belong to live runs, found again after the restart; `dispose: true` disposes them too), waiting for the creates, every disposal it started and every create a settled run's release aborted at most `CLOSE_TIMEOUT_MS` 30 s, then reports what is left to `onError` and resolves (call after `engine.drain()`); `release(runId)` aborts and waits for the run's creates in flight too; afterwards `acquire`, `get` and lookups reject. A workspace created while its run was released is disposed. `deployment` (default `DEFAULT_DEPLOYMENT`) scopes `create`, `find` and the garbage collection, so deployments sharing one Docker host or namespace never see each other's workspaces.
- **Context and module**: `provideSandboxContext(engine, manager)` / `injectSandboxContext(ctx)` (key `sandbox`) in the main entry, so a tools factory builds `manager.tools()` and `codingTools(manager)` per execution. `sandboxModule()` on `@chamvi/sandbox/module` picks the provider (`CHAMVI_SANDBOX_PROVIDER`, else the option, else `local`) and the deployment (`CHAMVI_DEPLOYMENT`, else the option, else `default`; there is no app name to fall back on), builds `.manager` when called with `isSettled` answered through the engine's `getRun` (a `completed | failed | cancelled` run, a missing one only with a named deployment (`CHAMVI_DEPLOYMENT` or the option), since apps sharing a host in `default` would remove each other's live workspaces; false before `engineCreated`) and `isSuspendable` (a `waiting` run whose `updatedAt + suspendAfterMs` passed; `CHAMVI_SANDBOX_SUSPEND_AFTER_MS`, else the option, else `SUSPEND_AFTER_MS` 30 min, `0` disables; effective up to `gcIntervalMs` later), on kubernetes only `persistence` from `CHAMVI_SANDBOX_PERSISTENCE` (`true`/`false`, wins over whether the option is set) and `CHAMVI_SANDBOX_STORAGE_CLASS` (wins over `storageClassName`), imports the provider package in `setup` by variable specifier (`SANDBOX_PROVIDER_PACKAGES[name]`, structural types: a literal import would make `build:types` need the provider's `dist`, a build cycle since every provider peers on `@chamvi/sandbox`; the providers are in none of sandbox's dependency fields, not even as optional peers or a devDependency, since release-please's graph would close `sandbox <-> provider`: the import resolves from the installed tree (npm and pnpm's default hoisting; under Yarn PnP or pnpm `hoist=false` pass `options.provider`)), and its hooks attach the manager and provide it (`engineCreated`; in start mode also `startCollector(engine.clock)`: `manager.collectGarbage()` every `gcIntervalMs`, default `GC_INTERVAL_MS`, none for 0, at most `GC_INTERVAL_MAX_MS` 2^31 - 1 (a larger Node timer fires after 1 ms), re-armed after each collection settles, a failure reported) and stop the collector, then `detach()`/`close()` it after the drain (`close({ dispose: true })` when `engine.store.runs` is a `MemoryRunRepository`, whose runs no restart resumes); migrate mode does nothing. Git credentials: the `credentials` option, then `staticGitCredentials()` of `CHAMVI_GIT_TOKENS` (JSON; an error names the variable and the entry), then one delegating source over `AppToken.GIT_CREDENTIALS` (read with `resolveAll` once `setup` ran, so contributions of modules set up later count), so a module-built manager always has a source; workspace-installed credentials are the only mode: `CHAMVI_GIT_CREDENTIAL_MODE` (non-empty) and a `credentialMode` option of `sandboxModule()` or `createWorkspaceManager()` (removed in 0.4) are an `InvalidAgentDefinitionError` naming them, since ignoring a former `tools` mode would hand bash the write token.
- **Security model**: local isolates nothing. Docker and k8s are a code-execution boundary (root inside by default, never privileged, no host mount but the cache, `no-new-privileges`), not a network boundary: on `bridge` a workspace reaches the host gateway, other containers and cloud metadata, on k8s every cluster service, until 011's NetworkPolicy (select `app.kubernetes.io/component=sandbox`, deny all egress but GitHub and npm, deny the chamvi namespace and metadata) or a host firewall. Docker socket access is root on the host (socket proxy or rootless Docker). No credentials in URLs, `credential.helper` reset, no host or chamvi environment, no service account token.
- **Image**: `images/sandbox-dev` (`debian:trixie-slim` + git, ca-certificates, curl, tini, ripgrep, jq, build-essential, unzip, xz-utils, mise and the GitHub CLI (unpinned) from their apt repositories (Git helper credentials do not authenticate gh); root; `/workspace` 0777 and `/cache` 1777, which Docker copies into empty volumes, so the hardened mode writes them; mise's data dir its default `$HOME/.local/share/mise` (toolchains per workspace, never in `/cache`), `MISE_SHIMS_DIR=/home/sandbox/.local/share/mise/shims` (per workspace, on disk, kept across a restart: never on the PATH from a shared cache), `MISE_YES`, `MISE_TRUSTED_CONFIG_PATHS=/workspace`, idiomatic version files for node, python, ruby, go, java, `PATH=...:/home/sandbox/.local/share/mise/shims` (appended), `DEBIAN_FRONTEND=noninteractive`; no language toolchain), `ghcr.io/chamvi/sandbox-dev` tags `trixie` and `trixie-<short sha>` (the latter only on a push to `master`), `linux/amd64` + `linux/arm64`, built by `.github/workflows/images.yml` (a smoke test on PRs touching `images/**`; pushed through `tada5hi/craneship` on `master` and weekly). `DEFAULT_SANDBOX_IMAGE = 'ghcr.io/chamvi/sandbox-dev:trixie'`; pin a digest in production.

## Testing

- Sandbox providers run `describeWorkspaceContract(name, factory, { find? })` from `@chamvi/test-kit` (`factory({ runId? })` returns a fresh repo-less workspace; the suite disposes it; `find` is a second provider instance's `find`, which runs the section that drops a handle and finds the workspace again with its files). It is the documented exception to the `IClock` rule: it runs real processes with short real timeouts (timeouts, process-group kills, floods), as does the Docker suite. `@chamvi/sandbox`'s tests use a private `test/utils/clock.ts`, scripted workspaces (`test/utils/workspace.ts`), a fake provider (`test/utils/provider.ts`) and a fake transport (`test/utils/transport.ts`). Checkouts use `createGitFixture(files)` (branch `main`, tag `v1`) with `allowFileRepos: true`. The credential specs drive scripted workspaces (`createFakeProvider({ onExec })`, recognizing `INSTALL_CREDENTIALS_SCRIPT` and `GIT_AUTH_SCRIPT`); `test/unit/git/scripts.spec.ts` runs the helper scripts with real `sh` and a fake `git`. `@chamvi/sandbox-local`'s `test/unit/provider/git.spec.ts` runs the whole flow against a private https host: `startGitServer()` (`test/utils/git-server.ts`, a self-signed loopback certificate from `openssl`, `git http-backend` behind basic auth, trusted through `GIT_SSL_CAINFO` in the workspace env), skipped locally when `openssl` or `git http-backend` is missing, never in CI.
- `@chamvi/sandbox-docker` tests need Docker: `test/global-setup.ts` gates on dockerode `ping()` (skip with a warning locally, fail when `CI` is set), builds `images/sandbox-dev` as `chamvi/sandbox-dev:test` once per run and removes leftover `test-` run containers and the test cache volume `chamvi-sandbox-cache-test` at the end (specs build providers with `dockerOptions` from `test/utils/docker.ts`, naming that test volume, never an operator's); `describeDocker()` (`test/utils/docker.ts`) skips a suite without Docker. Tests that reach the network (clone a public repository, pull an image) are skipped when `CHAMVI_OFFLINE` is set. `test/unit/coding.spec.ts` runs `codingTools()` (a devDependency on `@chamvi/coding`) in a `sandbox-dev` container: dash as `/bin/sh` (and as the inner shell through a `bash` shim), ripgrep and GNU `timeout`, which the macOS host of the local provider lacks. `@chamvi/coding`'s own tests run on the local provider, whose host `PATH` has no ripgrep, so they pin the `git grep` and `grep` engines.
- `@chamvi/sandbox-k8s` tests never reach a cluster: the provider takes a fake `IPodClient` (`test/utils/client.ts`) on a `ControllableClock`, and `createPodClientFrom()` is tested with fake `core`/`exec` parts. A real cluster is a manual check (kind, a least-privilege service account, the plan's steps).
