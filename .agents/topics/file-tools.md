# File Tools

Read before changing `@chamvi/tool-files` or its interpreter boundary. Dependency interfaces and upgrade risks: [just-bash](../references/just-bash.md).

- **Call scope:** every `process_files` invocation creates fresh files, environment and cwd. Import only explicitly selected current-run artifacts; automatic previous-call state would break replay and parallel-call independence.
- **Ownership and bounds:** validate complete selections before artifact access; prove input ownership and aggregate metadata size before reading bytes, then recheck actual bytes. Stage and validate every output before any put. Raw output files retain bytes; diagnostic text has a combined UTF-8 cap. The private scratch floor accommodates synthetic files without relaxing artifact caps.
- **Artifact identity:** output keys hash JSON `[toolCallId, normalizedPath]` under `process_files:`. Filename-only keys are rejected because separate calls must not overwrite artifacts referenced by earlier checkpoints. Same-call replay replaces its own IDs. Computation is not an effect and can repeat on simple-agent approval replay; completed model steps use checkpoints. Cancellation stops further puts once observed; completed puts cannot be rolled back.
- **Trust and capability:** both tools taint results/errors. Execution is pure computation over guest files, with the fixed command allowlist and hardened budgets. Do not add a host filesystem, inherited host env, networking, custom commands, optional language runtimes or raw tool executors. Outbound and other host effects stay in their existing tools and gates. The interpreter is in process, not VM isolation; Docker/Kubernetes workspaces own real executable workflows.
