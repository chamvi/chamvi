# File Tools

Read before changing `@chamvi/tool-files` or its interpreter boundary. Dependency interfaces and upgrade risks: [just-bash](../references/just-bash.md).

- **Call scope:** every `process_files` invocation creates fresh files, environment and cwd. Import only explicitly selected current-run artifacts; automatic previous-call state would break replay and parallel-call independence.
- **Ownership and bounds:** validate complete selections before artifact access; prove input ownership and aggregate metadata size before reading bytes. Stage and validate every output before any put. Raw output files retain bytes. Returned diagnostics share 65,536 UTF-8 bytes, stderr first, with `[output truncated]` inside the cap on clipping and intact code points. Interpreter work output is separately bounded by `max(65_536, maxBytes * 4)` because redirections and pipeline stages consume it. Private scratch is `65_536 + maxBytes * 2`, reserving synthetic files alongside full selected input/output room without relaxing exact artifact caps.
- **Artifact identity:** output keys hash JSON `[toolCallKey(context), normalizedPath]` under `process_files:`. The opaque core key includes run, step and call identity (#171). Filename-only and SDK-call-ID-only keys are rejected because separate calls must not overwrite artifacts referenced by earlier checkpoints. Same-call replay replaces its own IDs. Computation is not an effect and can repeat on simple-agent approval replay; completed model steps use checkpoints. Cancellation stops further puts once observed; completed puts cannot be rolled back.
- **Trust and capability:** both tools taint results/errors. Execution is pure computation over guest files, with the fixed command allowlist and hardened budgets. Do not add a host filesystem, inherited host env, networking, custom commands, optional language runtimes or raw tool executors. Outbound and other host effects stay in their existing tools and gates. The interpreter thread is not VM isolation; Docker/Kubernetes workspaces own real executable workflows.
- **Preemption:** `runner/module.ts` runs each call on its own `worker_thread` (`dist/worker.mjs`, a second tsdown entry) with an empty env and a heap limit, and terminates it on abort or at `timeoutMs + 2 s`. Never call just-bash on the main thread: its limits are checked between operations, so one long `diff` or `sed` blocks the event loop, and every run in the process loses its lease. The worker imports only just-bash and its own folder: under tests it runs from source without vitest's aliases. Keep `FILES_RECORD_BUDGETS` proportional to the byte limit; deadline and heap, not those counts, bound the cost.
