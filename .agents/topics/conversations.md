# Conversation Memory

Read before changing conversation recall, notes, trusted intake or their stores.

Conversation recall and explicit notes use optional `IStore.conversations: IConversationRepository`. `AgentDefinition.conversation: true` (or `{ key: string }` for a stable memory key across renames) requires both that storage capability and `EngineOptions.conversations` policy (`authorize`, optional limits). Ordinary runs remain unbound. `createApp({ conversations: { authorize, limits? } })` copies policy into `AppContext`; the built-in store module registers one `AppToken.STORE` aggregate from `createDatabaseStore()` or `createMemoryStore()`, including conversations. Custom capabilities enter through `storeModule({ store })` and own their schema/connections/lifecycle. All TypeORM roles share one DataSource. No new env variables or conversation retention timer are added, and ordinary migrations install the schema independently of opt-in. Check mode creates no identity or migration writes. Engine drain waits for journal/reconciliation before an app-owned DataSource closes.

Trusted intake uses `engine.channelContext(exactRegisteredChannel).dispatchConversation(envelope, { account, chat, audience, text })`; ordinary dispatch and `dispatch()`/`dispatchTo()` strip forged bindings. Identity is agent/channel/account/chat/audience, hashed canonically, with a monotonic generation. The adapter must supply authenticated routing, accepted text and an explicit audience; HTTP body fields do not create this trust. Policy runs before admission, recall/resume and memory-tool calls. Idempotency is identity-scoped and deliberately excludes generation, so reset preserves existing-run duplicates within the reservation lifetime. A missing-run reservation has no original-generation metadata: generation-zero healing remains, while post-reset/delete healing fails closed and requires explicit recovery or reservation expiry.

For a bound conversation, the current model message uses the accepted `ConversationTarget.text`, with ordinary attachment handling; the original trigger payload remains available to tools and audit storage. Existing checkpoints are resumed without rebuilding that input.

Run creation precedes turn ownership. `beginTurn` atomically stores accepted input, immutable bounded recall and the active owner; PostgreSQL mutators take the identity lock before owned rows. Conversation/run/effect repositories do not claim one transaction. Ordinary source-address emits are journaled pending before transport output, then confirmed against their exact effects. Terminal reconciliation marks remaining uncertainty unknown and releases the owner; failures retain ownership for lazy repair. Pending/unknown sends are inspectable and excluded from recall. Sent means `channel.out` resolved, not recipient receipt. Memory-bound transport waits observe execution cancellation even when an adapter ignores the signal; late transport completion cannot write a framework effect or confirmation. Normal completion, and a replayed pending call that pauses again or fails, waits journal work before publishing terminal status or pausing, for sends a tool did not await at most `CONVERSATION_SEND_GRACE_MS` 30 s on the `IClock` (`engine/execute/constants.ts`); then the execution's abort on exit ends them (`untilAborted`), they stay pending and terminal reconciliation marks them unknown, so a transport that never settles holds neither `pause()` nor `finish()`. Same-scope waiting/interrupted runs retain serialization and snapshots across restart.

Storage identity `agent` is the configured memory key (default agent name); authorization receives the actual agent separately as `ConversationAccess.agent`. Queued work with a changed configured key fails before recall. PostgreSQL conversation repositories share the run DataSource. Active owners and conversation child rows reference their runs; run/checkpoint scope bindings reference the local conversation row. Checkpoint and step run IDs also have foreign keys. Both store adapters share canonical validation, identity hashing and recall selection through `@chamvi/core/conversation/persistence`; PostgreSQL reads candidates in bounded pages and performs ID-only pruning. Conversation child rows reference their parent identity; fixed fields and run/checkpoint bindings are scalar columns, with JSONB only for frozen AI SDK messages. The pre-first-step snapshot lives only on the active conversation row and is cleared atomically with terminal owner release; ended runs cannot request historical snapshot replay. Note edits and their replay receipts commit in one conversation transaction; generic run effects do not provide that atomicity.

`memoryTools()` exposes list/get/set/remove only when explicitly composed into the agent's tools; `hasConversation(ctx)` checks the internal binding, never caller-editable run fields. Notes are untrusted user data, not system instructions. Note writes are atomic with metadata-only operation replay records; removed text is not retained in that ledger. Pruning requires both elapsed retention and settled/missing source runs before deleting operation tombstones; active/recoverable records remain. `inspectConversation`, `resetConversation`, `deleteConversation` and `pruneConversations` are privileged engine APIs, not public routes. Reset advances generation and optionally retains notes, with old transcript retention unchanged. Delete removes conversation-owned rows and retains the generation tombstone; runs, checkpoints, effects, provider logs and backups remain separate audit copies.
