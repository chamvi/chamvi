# Mail Tools

Read before changing `@chamvi/tool-mail`.

`@chamvi/tool-mail` holds two factories and `toolMailModule()` on `/module`. `mailTools({ accounts?, client?, timeoutMs?, clock? })` returns five read-only `defineTool()` tools (`mail_accounts`, `mail_search`, `mail_get`, `mail_attachment`, `mail_thread`) over one `IMailClient` (`createMailClient(accounts, { clock?, timeoutMs? })`). `mailWriteTools({ accounts?, client?, timeoutMs?, clock?, classifier? })` returns `mail_send` (SMTP) and `mail_delete` (IMAP `MOVE` to Trash) over a separate `IMailWriteClient` (`createMailWriteClient()`); an app that registers both gets two clients on the engine. It peers on core and `ai` (optional peer on app) and depends on `imapflow`, `nodemailer`, `postal-mime`, `unpdf`, `fflate` and `smob`, pinned to exact versions. Options are checked when called (`InvalidAgentDefinitionError`, never echoing a value: the password must not reach an error).

## Invariants

- **The read client is read-only on the wire.** `IMailClient` never sends `SELECT`, `STORE`, `EXPUNGE`, `MOVE`, `COPY`, `APPEND`, `CREATE`, `DELETE`, `RENAME`, `SUBSCRIBE`, `UNSUBSCRIBE` or `IDLE`, and never a bare `BODY[` fetch. Folders are opened only through `openMailFolder()` (`client/mailbox.ts`) with `getMailboxLock(path, { readOnly: true })` (`EXAMINE`; without `readOnly` imapflow sends `SELECT`); body fetches go through imapflow's `source`/`bodyParts`, which send `BODY.PEEK`. imapflow options always carry `logger: false`, `disableAutoIdle: true` and `clientInfo: { name: 'chamvi' }`. Never call `mailboxOpen`, `messageFlagsAdd` or anything else that writes. Proven by `test/unit/client/wire.spec.ts`: every tool (including `mail_attachment`) against the fake server, on a generic and a Gmail account, asserting an allowlist of command names (anything else fails), that no fetch names `RFC822`, `RFC822.TEXT`, `BODY[` or `BINARY[`, and that no `\Seen` flag changed (the fake sets it on a non-peek fetch and on `STORE`, as a server does).
- **Write client** (`write-client/`, never the read client): its wire allowlist is `LOGIN`, `LIST`, `LSUB`, `EXAMINE`, `UID SEARCH`, `UID FETCH`, `APPEND` (the Sent copy), `SELECT` only right before a delete's `UID MOVE`, and SMTP. It never sends `EXPUNGE`, `CLOSE`, `STORE`, `COPY` or `DELETE`, so nothing is ever deleted for good. `UID MOVE` needs a native move as imapflow decides it (`hasNativeMove()`, `trash.ts`: the `MOVE` capability, IMAP4rev2 enabled, or a rev2-only server; an advertised but not enabled rev2 is not enough); without it the delete fails and nothing moves, never imapflow's copy-and-delete fallback. Trash and Sent are the folders with the `\Trash` and `\Sent` special-use flag (covers Gmail and localized names), never found by name; without the flag a delete fails and a send skips filing (`filed: false`). Proven by `test/unit/write-client/wire.spec.ts` against the fake IMAP and SMTP servers.
- **Send** (`write-client/compose.ts`, `sent.ts`): the mail is built once from one input. The wire copy has no `Bcc:` header, the copy appended to `\Sent` keeps it. Both carry `X-Chamvi-Effect` (`MAIL_EFFECT_HEADER`, `effectMarker(key)`) and a `Message-ID` derived from the marker, so a retry builds the same mail. `alreadyApplied` searches Sent for either header (an `OR`; on Gmail `rfc822msgid`) and returns the recorded result when found. Nothing throws after SMTP accepted the mail: a failed filing is `filed: false`. A timeout, an abort or a broken connection after DATA was handed over (before the 250) fails with the reason `timed out after the message was handed over; it may have been sent`. A refused recipient is reported by address; accepted ones still receive the mail. Addresses must be printable ASCII (`/^[\x21-\x7E]+$/` plus the address pattern); the subject refuses control, zero-width (U+200B-U+200F) and bidi (U+202A-U+202E, U+2066-U+2069) characters, so the approval shows what is sent.
- **Approvals.** `mail_send` always asks, with the whole mail in the approval (header lines, `--- mail text ---`, the text). `mail_delete` runs the limit first (its own, `mailWriteTools({ deleteLimit })`, default 20 deletes per hour, bucket `deletes`, `onExceed: 'approve'`, bound to the tools' client source). Its `detail` records what the approval showed through `once(ctx, 'mail_delete:limit-listing', ...)` (the listed ids, `null` when only the `<folder> uid <uid>` fallback could be shown); `execute` skips the classifier and the delete approval only when `toolLimitApproved(ctx)` and that record covers every id (rejected: `toolLimitApproved` alone, which trashed mails the owner never saw listed). An agent `limits.mail_delete` entry replaces the tool's limit whole and records no listing, so its approved calls still run the classifier path. A call that passed the limit counts even when the delete approval then refuses it. Otherwise a classifier (`write-tools/classify.ts`, core `extract()`) sees from, subject, folder and date of each mail only and answers `routine` or `ask`; a failure or timeout is `ask`. The verdict goes through `once(ctx, 'mail_delete:classify', ...)`, so a resume after a denial does not classify again. Both approvals go to the source chat only when `await handle.direct()` is true, else to the inbox and API only (group chats never see mail content). One call deletes at most 20 distinct ids (input validation, before the limit counts).
- **Setup.** `mailWriteTools()` needs `engine.limitService` because `mail_delete` carries a default limit, unless `deleteLimit: false` or the agent sets `limits: { mail_delete: false }`. A stored-only account whose smtp settings are refused keeps reading: `smtp` is dropped with a warning and the connection is listed incomplete. An account sends only with `smtp: { host, port?, security? }` (port 465, 587 or 25 by `tls`, `starttls`, `plain`; the IMAP user and password log in to SMTP); `mail_accounts` and the send input refuse an account without it.
- **Accepted double-send window.** A mail accepted by SMTP but not filed to Sent (`filed: false`, or no `\Sent` folder), whose run crashes before the effect record, is not found by `alreadyApplied`; the replay reuses the recorded approval and sends again.
- **Mail ids** (`client/ids.ts`): `<account>:<base64url(folder)>:<uidValidity>:<uid>`, issued only by the tools. `parseMailId()` refuses anything `encodeMailId()` did not issue (round-trip check of the folder, uid 1 to 2^32 - 1). `inMail()` checks the folder against `isAllowedFolder()` (the account's folders, else every selectable listed folder, plus Sent) **before** any `EXAMINE`, then the UIDVALIDITY after it; an unknown account, an unlisted folder, a changed UIDVALIDITY or a missing uid is a `ValidationError` tool error (`MAIL_STALE_ID_MESSAGE` for the last two).
- **Folders** (`client/folders.ts`): `LIST` and `LSUB` once per client (cached per account, no `STATUS`). Default search scope: `account.folders` if set, else on Gmail `\All`, else every selectable folder but `\Trash`, `\Junk` and `MAIL_EXCLUDED_FOLDER_NAMES`. A thread adds Sent (Gmail with the default scope: All Mail only).
- **Gmail** (`gmail` defaults to `host === 'imap.gmail.com'`): `query` is `X-GM-RAW`, threads by `X-GM-THRID`; elsewhere `query` is `TEXT`, threads by `HEADER Message-ID`/`In-Reply-To`/`References` over the mail's own id, its In-Reply-To and its last `MAIL_THREAD_MAX_REFERENCES` (10) References, deduplicated by Message-ID.
- **Caps** (`text/constants.ts`, `client/constants.ts`): body pages of `MAIL_BODY_MAX_CHARS` (50 000), attachment text pages of `MAIL_ATTACHMENT_MAX_CHARS` (20 000), both by `offset`/`nextOffset` (never inside a surrogate pair, an offset past the end a `ValidationError`); PDF the first `MAIL_PDF_MAX_PAGES` (50) pages, page by page (unpdf's `extractText` reads all); OOXML parts read only when named by `OOXML_TEXT_PARTS`, declaring at most `MAIL_ZIP_PART_MAX_BYTES` (10 MiB), at most `MAIL_OOXML_MAX_SLIDES` (200) slides (and as many worksheets) and `MAIL_ZIP_TOTAL_MAX_BYTES` (20 MiB) declared in all, and inflated by `extractOoxmlText()`'s own streaming inflate in 1 KiB input steps that stop at the declared size and the remaining total (never `unzipSync`'s inflate: with a fixed output buffer fflate keeps decoding a lying part's whole stream into dropped writes, seconds of blocked event loop), parts read until the text passes 5x `MAIL_ATTACHMENT_MAX_CHARS`; `subject` cut at `MAIL_SUBJECT_MAX_CHARS` (1 000), `from`/`to`/`cc` at `MAIL_ADDRESSES_MAX_CHARS` (2 000), each invite field at `MAIL_INVITE_FIELD_MAX_CHARS` (500), at most `MAIL_INVITES_MAX` (10) invites per mail; HTML cut at `MAIL_HTML_MAX_CHARS` (1 000 000) before the linear-time `stripHtml()` (no backtracking regex on untrusted input; an unterminated `<script` runs to the end); a mail above `MAIL_FETCH_MAX_BYTES` (25 MiB, by `RFC822.SIZE`) is not fetched (`truncated: true`, headers and attachment list only), an attachment above it gives `(text extraction failed)`; search and thread `limit` 20 by default, at most 50, newest first by date (uid order is arrival, not date: with more matches than `limit` a folder dates its highest `MAIL_SEARCH_DATE_CANDIDATES` (1 000) uids by `ENVELOPE`/`INTERNALDATE` first), `truncated` when more matched.
- **Attachments** (`attachment/`): `extractAttachmentText()` never throws; any failure (broken file, abort) is `EXTRACTION_FAILED_TEXT` without the cause, which may quote content. An xlsx is read from its worksheets (`attachment/xlsx.ts`, `indexOf` scanning): one line per row, cells tab-separated in their column (`r`; omitted cells stay empty columns up to `MAIL_XLSX_MAX_COLUMNS` (256), a later one follows the row's last cell), shared strings resolved by index, inline strings, booleans and values as written. Calendar parts are not extracted: `mail_get` summarises them as `invites` (`icsSummary()`). Attachment bytes are never returned or stored.
- **Errors and timeouts** (`client/pool.ts` `MailConnectionPool.run()`): each call runs in the account's queue (one mailbox open per connection, `client/queue.ts`), raced against `timeoutMs` (default `MAIL_TIMEOUT_MS` 30 s, connecting included) on the `IClock` and the run's signal. A timeout or abort drops the connection (the next call reconnects). Every failure that is not a `ChamviError` becomes `requestError()`: code `mail_request` (`MAIL_REQUEST_ERROR_CODE`), message `<tool>: <account>: <reason>` with a reason from a fixed set (`login failed`, `cannot connect`, `timed out`, `request failed`, `no thread id`), never the server's text, a credential or content.
- **Trust**: every tool taints (`taintOf(source)`: decided before the call from the client, `false` only for the unconfigured client's `configured: false`, which reads nothing; never from a result) and its description ends with `UNTRUSTED_NOTE` (the tool-web wording, for mail).
- **Env contract** (`module/helpers.ts`, read when `toolMailModule()` is called): `CHAMVI_MAIL_ACCOUNTS` (`MAIL_ACCOUNTS_VARIABLE`) is a JSON array of `{ id?, address, host, port?, security?, folders?, gmail?, smtp? }`; `id` defaults to the address with `@` and `.` as `-`; credentials `CHAMVI_MAIL_<ID>_USER` (default the address) and `CHAMVI_MAIL_<ID>_PASSWORD` (in env or the store: checked in `setup` through `resolveConnection`, missing from both fails naming the variable, never at the factory), `<ID>` upper-cased with `-` as `_` (two ids that collide there are refused), each also as `<name>_FILE` (one trailing newline trimmed; both forms set is an error). Errors name the variable and index, never a value. The `accounts` option replaces the variable. In `setup` (`module/type.ts`) stored rows of type `mail` named `mail-<id>` are added and merged per field through `resolveConnection` (for an account of the JSON variable that variable and the credential variables win; a stored-only account reads no variable, a `CHAMVI_MAIL_<ID>_*` one named after it is ignored with a warning naming it (#197), and its gap is listed `incomplete` and not used); the `accounts` option pins the set, the read is `readStoredConnections()` (`@chamvi/app`: a check writes nothing, and on a store behind its migrations warns and continues env-only; an unreadable row lists the account `failed` and unused, unless env sets its password), a stored setting the client refuses on a declared account is dropped with a warning and the account listed `incomplete` so the dashboard stays reachable, a name above 64 characters is used but not listed, and an app without a connection service stays env-only. No accounts: the context stays provided and each tool fails with `connection_not_configured` (`mailTools()` outside the module still fails with `context_not_provided`). Migrate mode does nothing; the client logs out on `drained` and in `teardown`.
- **Privacy**: the package has no access control of its own. Tool results land in the run's steps and checkpoints, and the model's answer is mail-derived, so whoever reads the agent's runs reads the mail; such agents should be `private: true` (only `agent:<name>:read` reads them), as the README and examples show. Credentials stay in the client: never in a tool input, a result, an error or a log.

## Testing

- No test reaches a real server. `createFakeImap()` (`test/utils/imap.ts`) is an in-process IMAP server on 127.0.0.1 answering the commands imapflow sends (LOGIN, LIST, LSUB, EXAMINE, UID SEARCH, UID FETCH with BODYSTRUCTURE, X-GM-THRID and partial `BODY.PEEK`), recording every command line (`commands`); `loginFails`, `hold` (no reply, for the timeout tests on a `ControllableClock`) and `search` shape it. `genericFolders()`/`gmailFolders()` and `accountOf()` (`test/utils/mail.ts`) build the two account shapes; `setup()` (`test/utils/setup.ts`) wires server, client and tools; `createPdf()` (`test/utils/pdf.ts`) builds valid PDFs of any page count.
- Hostile input stays bounded: a 10 000-page PDF, a part whose headers declare 10 bytes for 512 MiB and 150 slides of 10 MiB (time and RSS bounds), more slides than the cap, a part above the cap, a huge subject, address list and invite, a broken PDF and docx, 5 MB HTML with an unterminated `<script` (`attachment/`, `text/` specs).
- `createFakeSmtp()` (`test/utils/smtp.ts`) is an in-process SMTP server (EHLO, AUTH, MAIL, RCPT, DATA) recording the received messages (`raw`, dot-unstuffed); `authFails`, `hold`, `rejectRecipient` and `holdMessage` (no answer to the end of DATA, for the hand-over timeout) shape it. The fake IMAP additionally answers `SELECT`, `UID MOVE` and `APPEND`. `createWriteEngine()` (`test/utils/engine.ts`) runs `mailWriteTools()` on an engine with a limit service and a scripted chat source (`direct` option).
